# M3.4 evidence infrastructure: pre-implementation gap assessment

Audit date: 2026-10-20. Existing M2.4/M3 calculators and recognition are preserved.

| Existing evidence/interface | Available | Gap / planned use |
| --- | --- | --- |
| M2.4 cached live events, Battles 5–9 | 86 move announcements, 3 qualitative HP-change messages, thousands of HUD samples; original videos and sampled frames exist | Consume cached source IDs/times and saved binding receipts; do not repeat OCR |
| Battle Log parser | Can assemble turn headings/log orders with overlap ambiguity flags | Selected production streams contain no verified turn-boundary events; historical log capture time is not execution time |
| Command cycles/checkpoints | Explicitly provisional cycles; forced-switch purpose may be unknown | Preserve as uncertain windows, never number them as game turns |
| StateEngine | Stable instance bindings, replay callback, HP/status/stages/field facts and explicit duration fields | Final state cannot supply earlier snapshots; one scoped read-only replay is needed to generate missing action snapshots, checkpointed per battle |
| Existing Duration/MechanicRules | Ticks supplied integer durations on explicit boundaries; simulator profiles distinguish verification | Add a read-only duration projection supporting uncertain duration sets and missing turn progress, without changing StateEngine arithmetic |
| TeamConfiguration v2 / TeamProfiles | Canonical identities, exact observed stats, reviewed immutable builds and explicit instance consumers | Preview rosters do not supply builds; SP display fields are not automatically SP. Require manual verified build metadata and battle-instance bindings; missing fields stay unknown |
| ChampionsStats / M3.1 / M3.2 | Maintained legal SP/alignment stat formula, forward damage and conditional effective-Speed mechanics | Reuse calculations, no damage inverse calls, no parallel stat formula; full combat modifiers beyond audited subset remain unknown |
| M3.4.1 | Strict admission, configuration posterior, independent subset per opponent/turn | Build comparisons from verified same-decision state; unknown actor/build/modifiers still exclude observations |
| Own HUD HP | Exact current/max integers exist; saved receipts distinguish accepted readings | Retain raw transitions, reject animation/coarse/unbound readings; attack adjacency alone is insufficient attribution |

Implementation plan: a separate append-only evidence reconstruction package with
turn grouping, duration projections, verified own-build access, immutable snapshots,
conservative HP attribution, and an M3.4.1 adapter. Existing StateEngine remains the
observable-state authority. Verified annotations supplement source events without
rewriting them. Offline manifests fingerprint inputs/dependencies, checkpoint each
new stage, and preserve previous successful artifacts. Real-data counts and
controlled validation are reported separately. No M3.4.2, M3.3 priors, commit, push,
or historical artifact deletion is authorized.

Follow-up source audit during implementation found additional historical evidence:
Battle 6's preserved `m238-live-2/reference/battle-log.json` contains six assembled
entries under displayed heading 4, duplicated in a recovery run. Cached Battle Log
frames also show heading 1 in Battle 5 and heading 3 in Battle 8. Small agent-reviewed
excerpts retain those partial historical contexts separately. They establish no
live execution timestamp or complete start/end boundary; they do not repair the
live streams or certify a common Speed-order decision. Recognition metadata's
`summary-log.json` is a processing summary, not additional battle-log observations.
