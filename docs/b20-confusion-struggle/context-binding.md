# B20 混乱自伤主体绑定：消息顺序与 HP 回退

2026-10-29。替代最初混乱实现的五秒关联方式。主体绑定不再使用时间或帧数上限，
不新增模块、身份框架、机制或伤害公式。原冻结 B20 benchmark 保持不变。

## 当前行为

主路径只查看已经处理的 Battle Message 顺序。“对手的风妖精正在混乱中！”保留该实例
的行动上下文，HUD采样、画面动画、预览等非战斗消息记录不消耗上下文；时间间隔不参与
绑定判断。下一条独立战斗消息若是自伤，绑定风妖精为来源和受影响实例；若是使出招式，
则正常记录该招式，不创建混乱自伤。其它独立战斗消息同样结束上一行动上下文。
主体仍须是同一个在场实例，不能借助唯一种类或唯一混乱状态猜测。

缺少提示时，“不知所以地攻击了自己！”先作为主体未知的原事件保存。现有 HP 结算视图
将该消息作为独立来源，并在下一条独立 Battle Message 开始处关闭窗口，隔断前一普通
攻击、羽栖、反伤或挣扎。窗口内只比较自伤消息当时在场的实例，使用既有受支持数值
观察、单位、身份及覆盖检查，比较之前记录的HP与窗口最终观察的HP。

只有一个在场实例有受支持的净下降时，StateEngine用现有回放路径补绑定；保留原事件ID、
原始未知主体和所有HUD观察，补绑定结果写在回执 resolved_event 中。它记录绑定依据、
前后HP证据ID和关闭窗口的消息ID，明确是结算后的推导，不是文本直接读到了主体。
多个下降、最终回到原值、无可靠前值/终值、单位或身份不兼容、存在竞争来源、窗口未完成
时，主体继续未知。其它宝可梦的临时下降必须按其最后观察值比较；替补席HP不参与竞争。

HUD不必持续可见；允许观察之间有遮挡。混乱结算以消息边界确认窗口内最后观察，而不要求
额外时间间隔或连续帧数。没有观察到的终点不会被补造。完整性不足的数值证据仍不用于
确定主体，且不会将显示百分比换算为绝对HP。

一次结算只有一个 before/after/delta；中间动画读数保留为原始HUD与段ID，不生成多次
混乱伤害。补绑定每次由当前有效回执及HP视图重新计算，更正、撤回或新增第二个下降会使
旧结论撤销。带snapshot callback的回放只发布一次最终回执序列。
