# M1.2 recognition audit — 2026-10-13

The integrated default uses PP-OCRv6 when its official weights are installed locally and an independent Champions thumbnail matcher when its checksum-verified local cache is present. Otherwise `auto` reports a Tesseract fallback. OCR, icon and context evidence remain visible in verbose JSON. On disagreement, identity status is `conflict` and no species or form is emitted. The regulation roster is never an icon search filter.

## Visual fit and algorithm

The Champions sprite art closely matches the Team Preview thumbnails in the supplied screenshot: on that screen all 12 thumbnails resolve to the visually correct species. The recognizer crops icons independently of OCR, scales each crop, renders transparent references over an estimated local panel color for a complete-library search, then refines the top 12 with alpha-masked multiscale color correlation. It accepts a mapped candidate only above the visual threshold and with a sufficient species margin. Ambiguous or below-threshold results stay unresolved. The form ID is emitted only when close candidates agree on one form; otherwise the result contains the species ID alone.

Visual scores are similarity measurements, not calibrated probabilities. The tiny dark Corviknight icon on the configuration screen and some battle HUD icons remain difficult: the matcher correctly abstains rather than replacing text with a different species. PokeAPI official artwork was less similar in format and was not selected as the primary UI template. The source-sprite Raichu comparison in `M1.2-raichu-source.json` distinguishes regular Raichu (26/26, similarity 0.950) and Alolan Raichu (26/10202). These are source-derived composites on a panel color, not independent gameplay captures; no held-out Raichu capture was supplied.

## Reproducible benchmark

`tests/fixtures/m12_ground_truth.json` contains 196 manually checked regions in seven captures, with image hashes, boxes, expected text or species/form IDs and split labels. Development captures: Team Preview and both configuration pages. Held-out frames: battle screenshot, move selection screenshot and two extracted video frames. The held-out frames appear to come from the same gameplay material and do **not** establish generalization across players, UI languages, devices or game updates. Form accuracy in real captures has only four labeled male Indeedee examples; the visual Raichu form check above is source-derived. OCR results are raw recognition text, before entity correction. Character error rate (CER) is edit distance divided by expected character count.

The sole PP-OCRv6 Pokémon-name miss is preview `大狃拉` → `大狂拉`; canonical fuzzy matching resolves Sneasler, supported by its independent icon. One ability reads `拨沙` for `拔沙`. The critical battle name `赛富豪` is read exactly by v6 and resolves as Gholdengo (National Dex 1000), while Tesseract reads it incorrectly. The actual CLI battle output is recorded in `m12-battle.jsonl`; it resolves Excadrill, Sneasler, Metagross and Gholdengo. `m12-preview.jsonl` records all 12 Team Preview species. The complete per-region predictions, scores, timing and individual failures are in the three `M1.2-*.json` benchmark files.

The benchmark uses the same boxes for all OCR engines. It uses pure model recognition for both text and numbers; the production `auto` backend uses PP-OCRv6 for both. Tesseract and v5 runs skip icons so the OCR comparison does not repeat an unrelated visual inference. Visual and fusion accuracy are measured in the v6 run. Raw Tesseract confidence filtering and resolver behavior follow the existing M1.1 API.

## Latency, memory and deployment

Measured on Apple M1 Pro, 16 GB RAM, Python 3.10.4, PaddleOCR 3.7.0/PaddlePaddle 3.3.1 CPU, with models already loaded. Mean per annotated region: Tesseract Pokémon text 145 ms, v5 76 ms, v6 **54 ms**; PP-OCRv6 icon search **1.16 s** per icon. The full 196-region benchmark took 17.4 s, 12.9 s and 59.6 s respectively; the runs include different icon work, so those totals are not an OCR-only latency comparison. Peak process RSS was about 208 MB, 1.00 GB and 1.14 GB. Local weights occupy ~73 MB (v6) and ~81 MB (v5). Per-region time excludes one-time model loading and downloading. The current visual matcher is too slow to apply to every icon of every real-time frame; caching/reuse across unchanged frames and faster visual indexing are future work.

## Reproduction

```sh
python -m pip install -e '.[ocr,test]'
python scripts/setup_ocr.py --backend all
python scripts/retrieve_visuals.py
python scripts/benchmark_m12.py --backend tesseract --no-icons --output reports/M1.2-tesseract.json
python scripts/benchmark_m12.py --backend paddle-v5 --no-icons --output reports/M1.2-v5.json
python scripts/benchmark_m12.py --backend paddle-v6 --output reports/M1.2-v6.json
python -m pytest -q
python main.py --image tests/fixtures/battle_screen.png
python main.py --image tests/fixtures/team_preview.png --verbose --json-out outputs/preview.jsonl
```

`scripts/build_identity.py` rebuilds the identity index from the pinned PokeAPI CSVs and a pinned Champions sprite checkout. To refresh, inspect new source-file commits, licenses, name/ID joins and thumbnail fit first, then update the pinned revisions/checksums deliberately, rebuild the index and cache, review unmapped/conflicting forms, and regenerate ground truth only after manual visual checking. Running M1.1's game-data refresher also requires rebuilding this M1.2 identity index before recognition, because the data manifest changes.

Remaining work for a broader accuracy claim: more independent battle screenshots, captures showing regular and Alolan Raichu in actual UI, more labeled alternate forms, varying resolution and language captures, and better handling of tiny dark and battle HUD icons. No perfect-accuracy claim is supported by this dataset.
