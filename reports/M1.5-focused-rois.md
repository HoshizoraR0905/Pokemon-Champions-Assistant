# M1.5 focused ROI / nominal 3-fps experiment

The message foreground proposal substantially reduces animated-background triggers on the existing development cache. The HUD and decision-control proposals have limited gains and insufficient natural-change validation. **Conservative production detection remains unchanged.** This is a standalone change-detection experiment, with no OCR/model calls, video decoding, scheduling rebuild, M2 reconstruction, commit, or push. It establishes neither sustainable 3 fps recognition nor a new processing-completion latency.

## Meaningful changes and limitations

**HUDs.** Bar signatures retain the colored-fill column endpoints/fraction and dominant red/yellow/green color candidate at every sampled timestamp, suppressing brightness changes that leave occupancy/color bands unchanged. Text changes and bar-only changes are separately tagged. A bar-only sequence is `bar_intermediate_or_display_change`, never a damage event. Controlled decreasing-bar modifications on a real HUD fixture verify that every intermediate level and timestamp survives; these are synthetic controls, not new natural-game labels.

The dense cache has no labeled continuous HP animation or active-HUD ailment change. Name/number fingerprint changes can also be compression or anti-aliasing differences; they are not confirmed HP changes. Status locations/grammar are not sufficiently labeled to declare them unchanged from white text. Residual indicator/portrait pixels, colored indicators inside text boxes, and all other raw HUD changes remain guarded by the full local raw envelope. The four HUD residual masks changed on all 26 visible dense samples. This experiment therefore does **not** establish reliable semantic separation of actual HP/status changes from all bar animation.

**Moves.** Names, PP, and highlighted selection are separate components; static-menu and arena-only-change regressions produce no extra menu proposal. Real dense/sparse samples still cause almost every menu proposal to fire, largely because exact foreground masks vary between encoded frames. The green-border candidate is visually checked on the 268-second menu; other highlight styles remain unvalidated and retain raw fallback. No tolerance/debounce threshold was promoted to suppress those changes. The isolated experiment supplies entry/change read proposals, not new OCR jobs or recognized move choices.

**Messages.** The proposal compares original white foreground pixels from left-anchored groups in the two checked text-line bands. Dilation only finds groups; the dilated mask is not used as the compared evidence. There is no minimum word/Chinese-character count. Synthetic short text and similar-consecutive-text changes are retained; an identical message after a clear produces a new trigger. Distant bright scenery can be suppressed. Faint/unanchored/occluded text, gradual reveal, background foreground-like shapes, and UI text overlapping the message area remain risks. Foreground equality is not proof that two observations are the same message, so raw-only differences stay ambiguous and the existing fallback is authoritative.

All **five reviewed message points** (178.0, 180.0, 182.4, 187.0, 191.0 seconds) are present and trigger both the foreground proposal and fallback in both dense comparisons. That is five point checks, not 100% message recall. No OCR was repeated.

**Party and replacement.** The list remains visible when the popover appears; they are separate interfaces/ROIs. The verified four-frame workflow preserves move-menu entry at 268 s, party-list entry at 270 s, replacement-popover entry at 280 s, and both exits at 282 s. List highlight differences are recorded independently from replacement/exit text. Purpose/commitment remains unconfirmed; no switch event is reconstructed.

**Targets.** Both verified 380/660-second target fixtures preserve all four card name/HP pairs and both possible banner positions. Cached visual review also confirms left-banner target cards at 195.2 s and right-banner target cards at 198.8 s. Their proposals survive thinning; the first appears at **195.4 s instead of 195.2 s**, a 0.2-second sampled detection delay. The existing classifier also produces a target label at 188.6 s during arena animation: that cached screenshot was visually checked and is a false positive, not a known target transition lost at 3 fps. Counts include such classifier candidates. The classifier and target recognizer were not modified to fix this separate issue.

Detector-only service is approximately 0.75 ms median / 3.31 ms P95 on the dense frames; it excludes phase classification, OCR, capture, persistence, and queue delay. It cannot be compared to the prior 15.281-second processing-completion P95 or used to claim the production latency target is met.

## Reproduce and disposition

```sh
.venv/bin/python scripts/evaluate_m15_rois.py
.venv/bin/python -m pytest -q tests/test_roi_experiment.py tests/test_streaming.py tests/test_monitoring.py tests/test_live_streaming.py tests/test_phase_timeline.py
```

The first command checks existing frame/fixture hashes and writes [per-ROI measurements](M1.5-focused-rois.json), `m15roi-*.jsonl` timestamped observations, and the annotated original-image overlays. It does not load OCR weights or decode video. Caches remain optional/unbundled.

Validation: **76 focused regression tests passed in 3.07 seconds**, including 11 new ROI tests. `git diff --check` passed.

The result supports further validation of anchored message foregrounds. It does not justify replacing conservative detection, reducing all monitoring to 3 fps, ignoring status pixels, or treating HP-bar movement as separate events. The experimental module is deliberately isolated from the streaming pipeline, and the existing conservative monitor remains the fallback.
