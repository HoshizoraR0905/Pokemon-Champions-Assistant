# M2.3.3-B1: video sampling and OCR candidate selection

Date: 2026-10-15.

## Result and scope

Implemented a separate scoped acquisition/selection entry point with a **2 FPS default**, configurable through `--sample-fps`. The same sampler supports 0.5, 1, 2, 3, and fractional rates. OCR invocation remains independent of acquisition. Historical M2.3.2 and M2.3.3-A paths and outputs were preserved; no fusion, parser grammar, move-name correction, damage, or Bayesian changes were made. No battle timelines were regenerated and no complete five-video OCR run was performed.

The recommended hybrid selects all 17 known audit misses; OCR recovers the annotated key phrase in **16/17**, with one missing move name left unresolved. In two manually inspected intervals totaling 24 unique video seconds, the 2 FPS hybrid captures and reads all six labeled message occurrences, using ten candidate read requests across 48 sampled frames. These are purposive diagnostic results, not full-battle accuracy or held-out recall.

## Configuration and CLI

Normal B1 entry point: `scripts/validate_m233b1.py`. The single acquisition setting is `--sample-fps`, whose default comes from `recognition.video_sampling.DEFAULT_SAMPLE_FPS = 2.0`. Historical scripts retain their historical schedules. Changing to 3 FPS uses the same global timestamp-grid implementation; there is no downstream hardcoded two-second scheduler in this path.

```sh
# Candidate selection only; no OCR by default.
.venv/bin/python scripts/validate_m233b1.py --battle-id sample_battle_0 --start 408 --duration 8

# Scoped message OCR using the existing installed ONNX environment.
.cache/m15-accel-venv/bin/python scripts/validate_m233b1.py --battle-id sample_battle_0 --start 408 --duration 8 --sample-fps 2 --policy hybrid --stage ocr

# Same pipeline, future supported frequency.
.venv/bin/python scripts/validate_m233b1.py --battle-id sample_battle_1 --start 214 --duration 16 --sample-fps 3
```

Both battle and finite positive interval arguments are explicit. Optional dependency: `pip install -e ".[sampling]"` supplies the measured `imageio-ffmpeg==0.6.0`; OCR needs the existing optional ONNX setup. The ordinary `.venv` lacks ONNX Runtime, so the actual new OCR experiments used `.cache/m15-accel-venv/bin/python` with ONNX Runtime 1.23.2, CPU, batch size 1, and the existing medium model. No model was replaced or downloaded.

Policies are `baseline`, `reduced`, `temporal`, and default `hybrid`. `--selection-config thresholds.json` overrides `SelectionConfig` fields, e.g. `{"stroke_value":120,"repeat_similarity":0.9,"repeat_window_seconds":2.0}`. Every policy/threshold is represented in the selection/run identity.

## Root cause and policy design

The original `_message_glyphs` counts connected white contours with V>200, low saturation, height/area limits, and then requires eight contours. It is not a character count. Readable short lines, faded strokes, and unusual glyph shapes can produce 0–7 qualifying contours. All 17 positive frames were already acquired, so these losses occur before OCR rather than between acquisition samples.

The legacy helper and legacy recognition gate were left unchanged. New policies compare exactly the same source images:

- **Baseline:** original >=8 glyph condition and legacy phase/time restrictions.
- **Reduced:** >=3 glyphs with the same legacy restrictions. This is a comparison policy, not the default.
- **Temporal:** message-ROI grayscale change (MAE >=8), with a first-frame bootstrap; it can select background animation and is not treated as a text detector.
- **Hybrid:** softer low-saturation luminance/stroke contrast evidence (gray >120; top-hat contrast >25), coherent character-height baselines near the message region’s left edge, and bounded repeated-text suppression. Defaults require >=4 aligned strokes, span >=50px, left anchor <45px, and maximum inter-component gap 40px at the standard 1311px frame width. It does not veto a candidate merely because the old contour count is zero.

The hybrid supports message/animation/unknown/battle-screen phases, excludes detected logs and known decision/menu phases, and compares stroke-mask overlap (>=0.9) to avoid repeating unchanged messages. Suppression expires after two seconds and resets when text/phase evidence disappears, so it is not a cross-turn global text deduplicator. Mask/phase heuristics select OCR work; they do not establish identity, an event, or a mechanic.

The initial broad soft-stroke attempt selected 17 of the 34 negative controls as well as all positives. Baseline alignment/left-edge/gap constraints eliminated those controls on this tuning set. This tuning history matters: the zero observed false positives below is not an unbiased precision estimate.

## Evaluation data and manual review

Curated references and labels are in `tests/fixtures/battles/m233b1_selection_diagnostics.json` and `m233b1_interval_labels.json`. They reference image checksums and timestamps rather than tracking extracted images.

- **53 existing cached diagnostic images:** 17 confirmed audit positives, 34 reviewed negatives (empty message regions, ordinary animations, HUDs, menus/unrelated UI), and two ambiguous fades. All 17 required positives are included.
- **Two repeated-image controls:** unchanged real message images from B0 198.017s and B4 578.013s, submitted twice 0.5s apart. These are deliberate duplicate controls, not new video observations. Baseline/reduced reselect both duplicates; temporal/hybrid suppress both. Raw OCR reused two compatible historical results and then hit their B1 cache copies, with zero new inference.
- **96 unique newly acquired source frames** in B0 [408,416) and B1 [214,230), shared across four rate schedules: manually labeled as 39 clearly visible message frames, 52 no-message frames, and five ambiguous fades. B0 contains Corviknight effectiveness and Indeedee fainting; B1 contains Liquidation, effectiveness, a Defense drop, and a berry notice. Source contact sheets were inspected before using OCR output for recovery scoring.

Negative and fade controls span different visual conditions; their images were inspected. Ambiguous fades are retained as a separate category, not counted as ordinary false positives or used to claim recovery. Distinct occurrences are manually assigned within each clip; they are not parser-generated event counts. The diagnostic positives and intervals were chosen because they contain relevant information loss and are not held-out samples.

## Measured cost and estimated full-video impact

The complete scoped comparison performed **138 new message read calls**, **198 predicted crops / 198 batches**, and **32.544s** inside OCR reads. This includes diagnostic controls and the union of candidate policies/rates, not just the recommended default. Per-read multiline segmentation can produce several model crops; read-call count is not crop count or message recall.

Peak measured Python-process RSS during OCR was **529.2 MB**. This is a process high-water mark across sequential model sessions; FFmpeg child peak RSS and per-policy independent peak memory are unmeasured. Acquisition used OpenCV 4.10.0; actual OCR evaluation used OpenCV 5.0.0 and ONNX Runtime 1.23.2. Saved selection decisions were subsequently verified under the project environment without changing the measurements.

Per-rate acquisition wall times are measured above, and selection wall times are measured in the policy table; raw per-policy OCR wall times remain in the local results and compact validation JSON. Whole-experiment end-to-end wall time, including all setup/checkpoint overhead, was not separately captured. A warm normal CLI run reused five existing B1 crop results, with zero new reads; repeated completed-run resumption also reported zero new calls. Original first-run cost measurements were preserved rather than overwritten by warm measurements.

For scale only, the five recordings total about 2,988s. An ideal global 2 FPS grid would request about **5,980 frames**, versus 1,496 existing survey frames (~4×); 3 FPS would request about **8,968**. VFR gaps and end boundaries can reduce actual emitted frames. These are arithmetic projections, not newly processed full-video results.

A naive extension of the inspected 2 FPS hybrid density (10 unique read requests / 24 video seconds) would be about 1,245 message reads over all five videos. Multiplying by the measured all-policy average read cost (~0.236s) suggests ~294s of inference. Acquisition extrapolation from the two short 2 FPS runs is roughly 460s, before selection, I/O, model initialization, cache effects, and different scene distributions. **These are not measured full-video costs, a runtime promise, or a recommended five-video job**: activity-biased clips, seek overhead, compression, frame storage, and false-positive rates can change them substantially.

## Cache, timestamps, and recovery design

- `recognition/video_sampling.py` uses rational target-grid construction anchored to recording zero and half-open chunk ownership. Source timestamps, nominal targets, and image hashes are separate. Fresh extraction parses integer source PTS/timebase rather than rounded `pts_time` text, preserving exact third-second boundaries; the original measured records retain their logged microsecond-level rounding. VFR source frames are selected by global grid cells; empty cells are recorded, not filled by duplicates/catch-up frames. The final partial cell is included if source evidence exists; no artificial end frame is manufactured.
- Source recording fingerprint, sampler version, FPS, and preprocessing/width identify acquisition caches. FPS numeric representations are canonicalized (2 and 2.0 agree). Compatible exact legacy samples and intersecting B1 grid targets can be borrowed with checksum validation. Changing the FPS does not delete or globally invalidate historical caches.
- New caches are isolated under `.cache/battles/<battle_id>/m233b1/`: `sampling/` for per-chunk frame manifests, `runs/` for configuration-addressed selection/OCR observations, `ocr/` for raw crop results, and `experiment/` for scoped benchmarks. Per-battle nonblocking locks reject duplicate owners.
- Run identity includes source, interval, sampler identity, policy/thresholds, relevant selection/phase code, and OCR configuration when used. Raw OCR is separately addressed by recording fingerprint, exact crop content/shape/bounds, backend code, model manifest/assets metadata, CPU/batch/multiline flags, and preprocessing contract. Thus a downstream replay edit or selection-threshold change does not itself require repeating compatible raw OCR.
- Frame timestamps remain in run observations even when identical crop recognition is shared. Compatible legacy raw message OCR was exercised explicitly by two unchanged-image probes; no legacy outputs were rewritten. No cross-battle raw recognition cache is shared.
- Sampling checkpoints validate image checksums and regenerate only invalid/incomplete chunks. Run manifests record completion/error and output hashes; completed runs validate their referenced image files. Raw OCR is checkpointed after every new crop result. A failed later stage preserves completed acquisition/recognition work.
- Benchmark result manifests pin source/selection inputs and the original cost record. `checkpoint` verifies stored decisions against current policy before sealing them; warm resumes keep first-run timing/call measurements rather than replacing them with zero-cost cache hits.

An early development probe exposed an FFmpeg option-order bug: an output duration combined with a filter that emitted no later frames could decode beyond the requested interval. That probe was stopped; its measurements are excluded. Final commands put `-t` before `-i` to bound input decoding. Regression coverage checks this ordering. A separate initial source-period-window attempt failed on VFR average-FPS assumptions and was replaced by the grid-cell sampler. Incomplete experimental folders were retained; no historical evidence was deleted.

## Validation, limitations, and B2 recommendation

- The broader focused regression command passed **98 tests**, covering sampling/selection, existing observable/hidden state, M2.3.2 reconstruction, M2.3.3-A evidence fusion, and artifact policy. The final sampling suite additionally covers synthetic VFR gaps and bounded episode-aware repeat suppression; the final focused run passed **19 tests**, including new-recording support and stale-fingerprint rejection. The original 98-test run and final focused run overlap and are not additive.
- Tests cover fractional rates, deterministic target order, segment boundaries, partial tails, VFR gaps, per-chunk repair/resume, cross-FPS reuse, independent sampling/selection/source/model fingerprints, faint text with zero old glyph contours, blank/menu/log exclusions, duplicate locks, raw crop reuse, completed-run resumption, and the labeled diagnostic regressions. Synthetic video tests need the optional FFmpeg package; image-based diagnostic tests have explicit local-artifact prerequisites.
- All **65** existing M2.3.2 and M2.3.3-A manifest outputs are checksum-verified unchanged without regenerating their timelines. Fusion and identity evidence rules were not modified during B1. Prior reviewed mechanics and hidden-state validation remain separate from automatic recognition selection.
- Text geometry is layout-specific, and thresholds were tuned using the diagnostic images. Very faint text, uncommon fonts/positions, camera clutter, overlays, or different layouts may still fail. No full-battle visible-message census, multi-hit recall, or held-out precision estimate was measured.
- The benchmark compares common source evidence fairly but only six occurrences across two intervals. Temporal-only selection wastes calls on animation; lowering the glyph threshold also admits negative controls. The hybrid is the justified provisional default for B2, not a claim of universal precision.
- For B2: retain **2 FPS + hybrid**, independent message-only OCR, the two-second repeat window, and existing cache identities. Begin with an independently labeled, previously unused interval in another battle and set a scoped inference/storage budget before any complete-video run. Measure per-message coverage and raw-text correctness separately from replay admission. Do not jump directly to all five videos or 3 FPS solely to increase candidate counts.

B1 stops here. Parser grammar, move-name repair, broader state replay, B2 processing, and M3.1 remain out of scope. No commit or push was made.
