# M2.3.3-C — independent cross-battle semantic validation

Date: 2026-10-15. Validation only; production recognition, parsing, state tracking and mechanics are unchanged. No M3.1 implementation, commit or push.

## 1. Findings and readiness

**Automatic video state is not yet reliable enough to supply damage calculations.** Clear HUD values are often recognized correctly, but coverage, stale occupancy, nickname attribution, missing move lines and incomplete stat/field evidence materially limit the resulting state. Successful unit tests and deterministic replay do not establish semantic acceptance.

| Readiness decision | Recommendation |
| --- | --- |
| M3.1 as an independent calculator accepting explicit, validated inputs | Reasonable to begin as a separate engineering task, with explicit unknown inputs and independently verified Champions rules. This validation does not verify damage formulas. |
| Feeding M3.1 from automatic video recognition | **Not ready.** Actor/occupancy freshness, missing moves and quantitative stages remain material blockers. |
| Actual real-time assistance | **Not ready.** Offline bounded throughput is promising, but streaming latency, full HUD/message coverage and semantic reliability are unproven. |

No numerical acceptance threshold was pre-established or invented after scoring. These recommendations follow the observed failure types and coverage limits, not a claimed accuracy target.

## 2. Method, provenance and independence

Prerequisites: reviewed AGENTS and the D/A/B1/B2 reports; clean starting tree; no competing OCR/video jobs; B1/B2 completion verified. `verify_m233b1.py` confirmed 65 M2.3.2/A outputs, 22 B1 sampling manifests, two complete runs and four experiment fingerprints/checksums. C additionally recorded and later verified 134 prior files, including B2 replay/recognition artifacts and prior reports. Existing viewers and milestone outputs were not regenerated.

Two primary intervals were selected after a sparse cached-image survey, before inspecting their new OCR outputs: **B2 292–304s** and **B4 450–458s**. Neither interval contains the B1/B2 diagnostic frames or the B1 benchmark intervals. This is purposive, message-rich sampling, not random footage or a held-out recording. Message labels were visually established independently of current OCR and replay predictions. A single Codex visual review supplied annotations; there was no second annotator or inter-rater study.

A 10 FPS reference census yielded 200 source-timestamped images, compared against the unchanged 2 FPS sampler/hybrid selector on 40 frames. Clear messages, no-message negatives and fading/ambiguous images were labeled separately. **This is not exhaustive native-frame video review**: sub-0.1-second messages may escape the reference grid. Therefore “sampling coverage” below is conditional on the reviewed reference, not proof of complete video recall. One Psychic occurrence is right-censored by the B4 interval boundary.

Nine separately reviewed HUD checkpoints cover all five recordings (36 slot observations). Eight checkpoints have cached automatic HUD OCR; B3's selected frame does not. Labels came from the actual images, including icons/models where display names are nicknames. Those images were used historically by the project, so the checkpoint set is not wholly unseen development data. The scored replay removes the matching image hashes and all later evidence. It measures held-out reconstruction, not a state agreeing with a HUD just fused at the same timestamp.

Fixtures:

- `tests/fixtures/battles/m233c_semantic_review.json`: six message occurrences; 200 frame labels (89 clear, 102 no-message, nine ambiguous); nine HUD checkpoints; four supplemental evidence cases. Labels include battle, timestamp, image/hash, side/slot/species where established, expected fact, confidence, evidence class and independence limitations.
- `tests/fixtures/battles/m233c_secondary_review.json`: supplemental HP/form/negative-menu review and the independently visible Politoed ability popup outside the ordinary message ROI. The ability-popup annotation followed primary OCR review; no rule or inference change followed it.

All fixture use is confined to evaluation/scoring and withholding. Recognition and replay event construction never import expected labels or corrected replay states. Direct UI/text evidence is separated from mechanical interpretation. Unknown targets, causes, exact move slots and unseen configuration stay unknown. Cross-switch identity continuity is not established by matching species alone.

## 7. Baselines and controlled differences

All baseline files are read only. M2.3.2 uses frozen video-event history and its original initialization, with initialization removed if its provenance is a held-out checkpoint (notably B2's first HUD). A controlled mode uses frozen pre-B2 parser source from commit `0a3cf19` with existing chronological fusion on the original automatic A inputs. It is a controlled parser/fusion mode, not a claim of running an archived interpreter/environment byte for byte.

| Comparison | Evidence control | Result |
| --- | --- | --- |
| Old glyph selector vs hybrid | Identical C 2 FPS images; no extra OCR for old selector | Selected occurrences B2 2/3→3/3, B4 0/3→3/3; total 2/6→6/6 |
| Pre-B2 parser vs B2 parser | Identical eight saved C OCR outputs | Both 6/6 occurrence types and 2/3 canonical moves; no demonstrated parser gain on these constructions |
| M2.3.2 strict prefix | Frozen legacy video/messages; HUD not chronologically fused | Identity 4 correct, 4 incorrect, 28 missing of 36; correctly attributed HP 0 correct, 8 incorrect, 28 missing |
| A controlled strict prefix | Original A automatic OCR/HUD inputs; reviewed checkpoint hashes withheld | Identity 18/36 correct; correctly attributed HP 13/36 |
| Current strict prefix | A inputs plus scoped C automatic messages in B2/B4 | Same checkpoint counts: 18/36 and 13/36; rain/Armor Cannon can still be admitted at their earlier times |

The M2.3.2/A difference includes admitting existing HUD evidence; it is not an OCR accuracy gain. Current-versus-A input differs in the two C intervals, so it is not a parser-only causal comparison. B1's sampling and selection remain separate from B2's parsing.

Historical cached interval message payloads are just one correct Armor Cannon occurrence plus two UI-corrupt fragments in B2, and none in B4. That is an input-schedule/selection difference, not evidence that B2 grammar alone recovered the new messages. No new 0.5/1/3 FPS experiment was run. The existing ~0.5 FPS survey is not an exhaustive reference, and the right-censored Psychic prevents claiming a whole-video sampling miss at the interval boundary.

The current measurement joins existing components in a validation harness: 2 FPS message acquisition/selection/OCR, chronological fusion and hidden projection. It is conditioned on historical cached HUD evidence outside the clips. It does **not** demonstrate a unified 2 FPS end-to-end HUD-and-message recognizer over five full videos or the streaming application's real-time behavior.

| 2 FPS acquisition | 1.802s / 24 frames | 1.266s / 16 frames |
| Selection | 0.430s | 0.295s |

| Inside OCR reads | 1.243s | 0.842s |
| Approximate Python peak RSS | 422 MB | 473 MB |
| Separate 10 FPS reference acquisition | 2.770s / 120 frames | 2.115s / 80 frames |

One B2 acquisition frame reused compatible legacy pixels; B4 reused none. The 40-frame acquisition throughput is approximately 13 frames/s, and the measured acquisition/selection/OCR stage sum is approximately 5.88s for 20s of footage. This excludes model startup, some orchestration/I/O, reference review, HUD recognition, and streaming scheduling; it is not end-to-end wall latency. Peak RSS is process high-water memory, cumulative across the two serial clips, and excludes FFmpeg child-process peak memory.

Current prefix replay is separately timed per recording (roughly 0.6–3.1s for the selected horizons; B3 has 155 historical prefix events). It is a full cached-prefix measurement, not incremental live-event latency. Exact per-mode timings and process high-water memory remain in `.cache/m233c/summary.json`. Repeat evaluation after annotation/provenance finalization reused recognition; cached replay results are fingerprint-addressed.

A warm run reused both reference acquisitions and both complete 2 FPS recognition runs with **zero current-invocation OCR calls**. Original successful recognition timings are preserved in C manifests. The first OCR-environment attempt failed before decoding/inference because it lacked `imageio_ffmpeg`; appending the existing `.venv` site-packages directory after the OCR environment's normal search paths supplied that already installed helper. No package/model installation or retry loop occurred.

Technical plausibility: 2 FPS plus selective OCR appears feasible for these short offline clips. Real-time readiness is not established: selection misses spatial UI evidence, model startup/sustained queues are not measured, and state correctness is inadequate. No full-video cost estimate or all-five-video recognition run is claimed.

Generated data stays under `.cache/battles/<battle>/m233c/` and `.cache/m233c/`. Per-run stages preserve acquisition/recognition and errors; a completion manifest pins 28 saved output JSON files plus code/fixture hashes. The prior-artifact manifest protects 134 files. Neither cache is a production override.
