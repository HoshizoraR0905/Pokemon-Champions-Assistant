## Fusion, hidden state and freshness contract

`visual_observation` carries direct source fields; `coverage_observation` records
an explicitly evidenced gap. Both require the opt-in profile and battle ownership.
Unplaced entry IDs, chronological HUD bindings and visual receipts use the existing
StateEngine. Retraction/correction replays remove dependent revelations; ambiguous
same-species instances remain unbound. Contradictory ability/item/max-HP evidence
is exposed with alternatives rather than silently overwritten. An absolute panel
stage does not reapply the earlier stat-change message.

HiddenEngine consumes admitted visual receipts for observed ability/item membership,
time-specific revelations and maximum HP. It does not turn observed ability into
native ability, observed item into a battle-start item, or a revealed move into an
exact slot. No damage, Speed, EV, nature or training-point inference is added.

Use `engine.evidence_projection(as_of=timestamp)` on a chronological prefix.
It returns detached data and does not mutate observable or hidden state. Each
projected fact includes value, knowledge category, last confirmation timestamp,
source confidence/parsing receipts, provenance, current support, uncertainty,
conflicts and known gap evidence. A request earlier than the state's evidence is
rejected, including future evidence embedded in an initial state.

Historical species revelation is distinct from mutable form/location/HP/stages/
item/ability state. Direct observations and deterministic derivations retain their
source categories. Between observations, this version does **not** assert complete
coverage or invent continuity: mutable values remain visible historically but are
`continuity_unverified`. There is no fixed expiration timer. A later timestamp
alone cannot certify the old occupant, even if a numeric HP value happens to match.
The legacy active-slot map remains available for compatibility; it is not the safe
current-state interface.

The projection includes turn, rule profile, instance IDs, stages, weather, terrain,
Tailwind/other side conditions, Trick Room, item/ability revelations, source times,
priority evidence and message/action observations. Supplied priority/timing evidence
is preserved without inventing it. Message/animation ordering remains explicitly
inadmissible for Speed comparison. M3.2 needs verified action order, order-decision
context, priority comparability and modifier coverage; none is fabricated here.
There are no imports or calls connecting this projection to M3.

## Reproduction and scoped resume

```sh
# Read-only cache/preservation verification.
.venv/bin/python scripts/validate_m234.py --stage audit
.venv/bin/python scripts/verify_m233b1.py
.venv/bin/python scripts/validate_m233c.py --stage check

# Defaults to cache-only; missing crops stop rather than silently invoke OCR.
.venv/bin/python scripts/recover_m234.py --requests .cache/m234/visual-requests.json

# One battle/mode at a time; completed compatible output is reused.
.venv/bin/python scripts/validate_m234.py --stage replay --battle-id sample_battle_2 --mode augmented
# Other modes: strict, persistence, inclusive. Other battle IDs: sample_battle_0..4.
.venv/bin/python scripts/validate_m234.py --stage summary
.venv/bin/python scripts/score_m234.py
.venv/bin/python -m pytest -q tests/test_m234.py tests/test_m233c_validation.py
```

Recognition manifests include request/code identity, status, output hashes and
errors; per-crop predictions are atomic. Replay manifests include input/code
fingerprints, battle ownership, output hashes and errors. For an interrupted stage,
repeat its scoped command. Do not reseal or regenerate the frozen C milestone.
New OCR requires explicit `--allow-new-ocr` and a bounded
`--max-new-predictions`; it is unnecessary to reproduce this completed result.
