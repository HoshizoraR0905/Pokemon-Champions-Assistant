# M2.3.6-U — UI regions, visual rows and occurrence-level review

Implemented on 2026-10-15 as an opt-in, bounded extension of the existing pipeline.
**Acceptance is partial.** The new path prevents the reviewed white-frame noise
from being scheduled, recovers the previously missed Coaching text, and emits
one candidate per inspected move occurrence. It still misses the grey isolated
HUD, cannot independently bind Coaching's actor across the coverage gap, and has
no verified move-description-overlay positive. No damage/Speed integration,
full-video processing, commit or push was performed.

Open the existing [review viewer](M2.3.6-review/review.html). Its original M2.3.6
counters remain frozen; a separate U panel explains the new results. Use the
category selector for the four large overlay modes and the reading-source
selector to compare the old and new OCR. The
[README](M2.3.6-review/README.md) contains the practical workflow.

## What changed and what safely entered state

The program now explicitly distinguishes expected geometry, pixel-supported
visibility, OCR selection, raw reading, canonical interpretation and state
admission. Existing detectors supply HUD, menu, popup, party, status and log
geometry; no replacement identity database or parallel Battle State was added.

On exposed diagnostic occurrences, fixed visual-row crops recover Fake Out on
its first sampled frame at **415.503333 s**, rather than waiting until the old
correct reading at 416.503333 s. Four compatible readings support one occurrence
and one executed-move revelation. Coaching is read at **425.505 s**, but the
existing tracker defers execution membership because its actor cannot be bound to
an observed current episode. Correct transcription is not sufficient for that
binding. Fake Out's target and damage effects remain unknown.

The white **408.001667 s** transition has no supported message glyph structure;
it schedules **zero OCR calls** in this path. The old `ype`, confidence .443,
remains available as raw historical evidence and had already been rejected.
It never becomes a valid-message miss or a Battle State event.

A literal flinch-prevented-action sentence now parses as an observational
`move_effect`, not an executed move. Its diagnostic state application remains
unresolved; no unobserved mechanical effect or numerical change is inferred.

## Baseline, reuse and staged execution

The working tree and active jobs were inspected first. Existing M2.3.4–M2.3.6
adapters, reports, curated fixtures, row selection, OCR segmentation and parser/
state entry points were examined. The existing M2.3.6 viewer, README, prediction
ledgers, observations/evaluations and seals were inventoried. The preceding viewer
is preserved at `.cache/battles/sample_battle_5/m236u/previous-review.html`.

The important existing pieces were:

- `Recognizer.classify`: preview, party/switch, target and battle/menu structure.
  Ordinary move-menu detection also depended on both sides' HUDs being visible.
- `identity_flow.hud_cards`: independent per-card name/HP checks; fading and grey
  cards remain incomplete. Hidden cards do not imply biological departure.
- `message_selection.features`: coherent character/baseline checks already exist;
  the M2.3.6 runner nevertheless invoked multiline message OCR unconditionally.
- `ONNXOCRBackend.read(multiline=True)`: brightness-profile segments, not a text
  detector with verified visual-row boundaries. Bright arena shapes can create
  extra OCR strips and fracture one visual row.
- `visual_evidence`, `party_panel`, `visual_adapter`: cached banners, selected
  detail panels, HP, items, abilities and stage arrows. Reused rather than copied.
- `battle_log.detect_log` / `assemble_views`: independent log geometry and
  historical scroll-row assembly. Reopening a log is not a new action.
- `m232_replay.reconstruct`: exact consecutive OCR-string deduplication. Different
  corrupt readings of one message can survive as separate candidates.

Work proceeded through saved audit/review, layout/row implementation, development,
implementation freeze, new test frames, diagnostic replay and review delivery.
Stage manifests and completed per-frame records are in the separate `m236u/`
namespace. The closed M2.3.5/M2.3.6 prediction budgets were not reopened.

## Source-specific layout and visibility contract

[ui_regions.py](../recognition/ui_regions.py) adds UI observation metadata; it
contains no authoritative battle facts. The initial profile is intentionally
limited to **1311×603** cached landscape images. A different resolution or UI scale
returns `unknown_layout` and does not apply the fixed message rows. This is a
limitation, not an assertion that larger source recordings are unsupported by all
existing adapters.

| Region / mode | Implemented evidence and semantics | Demonstrated limits |
| --- | --- | --- |
| Active HUD cards | Check each UI card separately using existing name-panel/HP structure; retain UI card index separately from logical slot and scene position | Fading 417.003 s card becomes partial; grey 460.01 s card still missed; no switch/faint inferred |
| Command / move menu | Existing four-row color/layout checks; independent of all four HUDs being present | Displayed choices do not imply execution; unknown layouts remain unresolved |
| Target selection | Existing banner and target-grid classifier | Target intent is not an executed action or confirmed target effect |
| Live message | Coherent glyph geometry plus calibrated visual-row bands before OCR | No frame is promoted merely because OCR returns a confident string |
| Field indicator | Top-left label/counter crops; exact supported literal label required | `4/5` is retained literally; remaining turns and trigger time are unverified |
| Ability banner | Existing dark-blue two-row detector; preserve screen edge and source bounds | Cached left-banner example only; no new right-edge validation; screen side does not prove battle side |
| Information / status panel | Existing detail selection and stage-arrow context takes precedence over superficially similar move rows | A selected panel subject is not a logical active slot; unlit stages stay unknown |
| Pokémon / Party Overlay | Existing party layout and selected-row adapter; cached fields reused | Reserve membership/HP never establishes active-slot occupancy; highlighted row is not a switch |
| Check Status Overlay | Verified selected-header/stage-arrow context; cached subject, HP, ability/item, stage and field extraction | Current displayed effects are not newly triggered effects; only identified subject/context can support facts |
| Battle Log Overlay | Existing wide panel/divider/scroll geometry; historical cached rows | Original event time stays unknown when unavailable; no live event is emitted on opening |
| Move Description Overlay | Explicit semantic category and parser/state guards | **No verified positive located; recognition untested.** Unrecognized large panels remain uncertain and cannot supply execution evidence |

A large recognized overlay occludes/supersedes ordinary HUD/message/command
interpretation. Unknown large panels are conservative `partial` overlays. The
status-panel/command conflict is resolved using the existing selected-header and
stage-arrow evidence: a broad purple panel alone is insufficient to distinguish
them. Ordinary battle crops are not applied to those overlays in this U path.
Opening or closing any overlay produces no inferred switch, condition transition,
faint or move execution.

Visibility states are `visible`, `partial`, `occluded`, `absent` and
`unknown_layout`. `partial` observations retain uncertainty. An expected box is
not evidence that a component exists, and an absent/occluded component is not an
ended condition or departed Pokémon. Some callers remain the legacy pipeline;
this task does not claim that every capture/streaming entry point now uses U.

## Message geometry, raw evidence and temporal occurrences

The fixed row bands are **y=411–443 and 444–478** at the verified native scale.
The existing `line_boxes` routine finds visual fragments; fragments are assigned
by pixel overlap/baseline to these bands and read in visual order. A row is not
split because it contains an English nickname, punctuation or separated glyph
components. A two-row sentence remains two rows. No expected message text is
hardcoded or supplied to OCR.

The old multiline routine can interpret bright background details as extra rows.
The new crops eliminate those erroneous strips in the inspected Fake Out and
Coaching cases. Original baseline text/confidence/tokens, new row bounds, raw
row tokens and the fragment boxes are retained for comparison. The ONNX backend
never supplied character-level detector boxes for historical tokens; missing
boxes are not reconstructed or invented. `regroup_tokens` also provides
baseline-based grouping for callers whose tokens actually contain boxes.

[message_occurrences.py](../recognition/message_occurrences.py) groups compatible,
chronologically consecutive **visible live-message** readings. It retains every
reading, handles OCR fluctuations, closes on absent/unsupported UI or a coverage
gap, and separates incompatible resolved move names. It emits at most one
semantic candidate per supported occurrence. It does not vote using future frames
or backdate the first supported reading.

A saved bad/bad/good Fake Out regression emits once at the third old reading,
416.503333 s; earlier prefix snapshots remain unresolved. With new OCR the first
reading itself becomes correct, so admission at 415.503333 s uses that frame's
new supporting pixels. This is earlier evidence availability, not future leakage.
Prefix replay retains no revealed Fake Out before that timestamp. Two rapid
identical messages without an observed boundary remain a broader ambiguity;
these few examples do not validate all deduplication scenarios.

`EventParser` now refuses live grammar when an explicit source-region type is
not `battle_message`. State policy independently prevents typed menu, overlay,
field or banner text from becoming a move execution. Legacy untyped callers keep
their existing behavior. No menu move, party choice, field counter, log row or
ability banner in this U adapter can reveal an opponent's executed move.

## Human review, overlay coverage and annotations

The existing offline viewer now offers separate categories for party, check
status, battle log and move descriptions, alongside HUD, move execution, command
menus, battle messages, conditions, abilities, information panels, animation and
unresolved observations. Missing verified categories display an explicit untested
empty state rather than a borrowed positive example.

The U comparison shows expected region, visibility, OCR selection/reuse, visual
rows, literal/canonical output, occurrence prefix and state-admission reasons.
Overlay review highlights/crops the overlay rather than applying the central
message box to its content. Readable primary explanations distinguish reserve
from active HP, displayed field conditions from triggers, historical log rows from
live events, and selected move information from execution. Raw tokens, scores,
bounds and provenance remain expandable.

Corrections support Correct, Incorrect assertion, No relevant UI visible,
Partially visible and Cannot determine, plus visible text, event type, actor,
target, species/nickname, HP, condition/counter or ability information, error
category and comments. Frame-level annotations record which OCR profile is being
reviewed. Structured browser persistence and JSON import/export remain separate
from frozen labels and production data; corrections never train or change the
pipeline automatically.

were reused read-only. There was **no frame extraction, video decoding, generic

## Regression and historical audit status

The pre-existing M2.3.4 source-freeze audit was investigated independently. Its
historical baseline includes `battle_events/parser.py`, but its intentional-change
allowlist excludes that path. M2.3.6's nickname normalization already caused the
incompatibility; U's region guard and observational flinch parsing add intentional
changes on the same path. The old audit and baseline are neither relaxed nor
resealed. Its failure remains a real reported source-freeze incompatibility, not
an absent-artifact skip or demonstrated cached semantic mismatch.

Focused tests cover region-type isolation, menu/log/description execution guards,
blank-frame OCR suppression, unsupported scales, geometry-only token grouping,
bad/bad/good prefix timing, repeated/different move boundaries, actual cached
status/log precedence, observational flinch and real diagnostic replay prefixes.
Existing state/hidden/visual/freshness tests and damage, inverse/stat feasibility
and Speed regressions are run separately; exact final counts and browser checks
are recorded in `m236u/completion.json`.

Remaining priorities are grey/fading HUD evidence and safe individual attribution,
current actor binding across gaps, surrender/other missing semantics, verified
move-description and right-banner examples, overlay transitions/scrolling and
independent examples from additional recordings. Sampling success and local
replay completion do not establish full-battle semantic acceptance or authorize
another milestone.
