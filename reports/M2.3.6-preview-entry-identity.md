## Existing architecture and implementation

The existing `Recognizer` already reads preview UI icons and stores a legacy
opponent-species set. The Battle 5 runner had not invoked that path. The old set
cannot represent repeated species, identify a nickname, or establish occupancy.
The audited exact-name regression also occurred before slot/instance binding:
text-conditioned icon support overwrote the independent text method while callers
serialized the original ambiguous icon.

This implementation extends existing models, canonical KnowledgeBase identities,
event schemas, StateEngine and evidence projection. It adds an **opt-in** path;
the ordinary capture/streaming entry points are not silently replaced.

| Files | Responsibility |
| --- | --- |
| `recognition/identity_flow.py`, `recognition/context.py` | Per-card HUD eligibility, preview observation rows, bounded entry follow-up records |
| `recognition/sprite_shape.py` | Independent silhouette comparison and explicitly dependent roster ranking |
| `recognition/identity.py`, `models/__init__.py` | Preserve independent text, independent icon and conditional evidence separately |
| `battle_events/aliases.py`, `battle_events/parser.py` | Shared nickname lookup normalization and collision handling |
| `recognition/identity_events.py`, `battle_events/schema.py` | Chronological preview, HUD, entry and explicit alias-revelation observations |
| `tracking/identity_ledger.py`, `tracking/evidence_fusion.py` | Replay-owned alias claims, prospective actor binding and re-entry evidence |
| `tracking/evidence_projection.py`, `tracking/reliability.py`, `tracking/state_engine.py` | Current-vs-historical episodes, explicit-gap handling and opt-in dispatch |
| `scripts/process_m236.py`, `scripts/evaluate_m236.py` | Scoped cache/budget orchestration, sealed evaluation and review generation |
| `tests/test_m236_identity.py`, `scripts/templates/m236_review.html` | Focused regressions and offline review interface |

The runtime path is `preview_rows` → `recognize_hud` →
`events_from_observations` → StateEngine with `reliability_v1`, `reliability_v2`
and `identity_v1` → existing evidence projection. It uses no reviewed species
answers, nickname dictionary, probabilities, usage priors or 3D-model coordinates.
Labels enter only the evaluation script. The demonstration runner deliberately
selects Battle 5; the recognition, normalization and tracking modules accept other
battle identities through their existing interfaces.

The alternate visible palettes and sloping/clipped HUD crops explain why plain
color agreement is insufficient; they do not prove shiny status or a form. The
silhouette method estimates the chromatic panel, excludes arena outside its hull,
rejects clipped/incomplete contours, compares alpha-mask shape and aspect ratio,
and uses engineering thresholds .86 / .10. These are not probabilities. It can
resolve species while leaving palette/form unknown. Original and silhouette
profiles are preserved separately; resolved species disagreement withholds
resolution. They are separate algorithms on the same pixels, not statistically
independent trials. Synthetic negative-shape and palette tests supplement the
real unforced ambiguous/unresolved outcomes; broad false-positive performance
outside these samples is unmeasured.

Roster-conditioned ranking retains only candidates supported by resolved preview
observations, attaches their provenance and is explicitly `ranking_only` and
dependent. It never turns a sole roster candidate into admitted identity. Sableye's
two unresolved preview views do not establish absence from the roster.

## Entry, nickname and admission contracts

Literal send-out announcements open eight-second follow-up records. The acquired
frames are inspected for readable HUD cards throughout each scoped window;
message OCR and HUD eligibility are separate. A window records subsequent HUD
evidence or expires unresolved, and does not assign an animation to a doubles
slot. Initial opponent and own lead messages are observed, but the first window
ends before a stable lead HUD: those follow-ups remain unresolved. The 284-second
own arrival is followed by HUD observations from approximately 287 seconds.
This is a bounded offline path over supplied frames, not automatic acquisition
beyond an evaluation window or a full-video entry detector. Repeated/raw entry
notices remain evidence and are not independent entry successes.

Nickname lookup uses **NFKC → casefold → remove whitespace**, retaining
punctuation. Raw strings remain separate. Normalization collisions preserve
competing claims and withhold resolution; equivalent lookup strings do not merge
individuals. Identically spelled names on opposing sides retain separate claims.
Opposing HUD text is treated as a literal display label even when it equals a
dictionary species name; independent icon evidence is required on that path.

Same-card admitted icon evidence can establish an alias. A separate route accepts
an explicit, high-confidence species revelation such as Mega Evolution. It creates
an unplaced observed episode when a current individual cannot be established.
Later messages use only prior accepted claims. Retraction reconstructs the ledger
and dependent revelations; it does not retrospectively resolve earlier messages.
Preview membership by itself never creates an alias.

The real run learns Invincible → Lucario from same-card independent silhouette
evidence in development, and Big Mom → Kangaskhan at **413.503333 seconds** from
the explicit transformation message. Big Nugget remains unidentified at admission:
its default HUD icon often correctly resolves Forretress, but scores around
.838–.841 fail the pre-existing .85 nickname gate. That threshold was not lowered.

Exact own-name observations retain `method=exact` when an independently ambiguous
icon is only conditionally compatible. The original icon remains ambiguous and
text-conditioned support is stored separately without asserting a form. Genuine
independent species/form conflicts are preserved. All three exposed Excadrill
contract regressions at 300.016667, 380.03 and 452.01 seconds now pass the species
admission check with the saved icon still ambiguous. This is a cache-only contract
regression, **not** regenerated old evaluation scores or a new independent test set.

## HUD scheduling and persistence

The scheduler checks each fixed UI card independently, allowing partial HUDs and
move-selection views while excluding team/target panels. It never uses arena
objects. Compatible OCR and icon crops are content-addressed. Rechecking the old
misses requests one opponent card at 256.01 seconds, two opponent cards at
346.025, and all four at 456.01. These are eligibility checks only: no new OCR or
new current-state score is claimed for those historical frames.

The new development scheduler still skips five full-HUD frames: 289.015,
289.515, 290.015, 293.017 and 293.517 seconds, losing 20 reviewed slot facts.
The held-out scheduler misses the initial partial HUD at 417.003333 seconds,
losing one reviewed fact. The UI-color/layout gate remains incomplete; camera
motion is not a demonstrated cause.

Explicit coverage gaps prevent species equality, a roster match or an old nickname
claim from proving current individual continuity. Candidate links to prior
same-species episodes remain unproven. A justified explicit re-entry preserves
move/ability/item revelations and clears old HP until directly observed again;
tests cover the move and HP behavior. Real re-entry of a specific biological
individual is not independently proven by these recording windows.

Resume exposed an additional projection issue: old unplaced arrivals from before
a coverage gap could veto fresh HUD occupancy forever. Under `identity_v1` those
historical arrivals are retained but no longer veto a newly observed episode.
No departure, switch or equivalence to the historical individual is inferred.
