## 判定规则

- 复用现有 `recognition/trainers.py:recognize_preview_trainers` 的区域和 OCR 后端；不修改模型、预处理或图标算法。仅在可信 `team_preview`（六选四）阶段读取标签，分开存储双方训练家观察：原文、NFKC/casefold/去空白的匹配形式、置信度、源帧、区域和时间。训练家观察通过新 `trainer_observation` 类型进入现有 `SideState.trainer`，不进入宝可梦身份库。UI 标签不等于已验证的唯一账号标识，`unique_trainer_id` 继续为空。

- 清晰观察要求置信度 ≥0.95，排除空值、明显截断和非法字符。成功后该方不再 OCR；不确定读取最多尝试三次，间隔至少两秒。暂时离开界面不会清空已读结果，进度随现有控制器 checkpoint 保存。上述重试与消失行为用模拟后端测试；本次真实缓存验证每方只试读一次。

- 开场双派出必须有此前可信预览上下文，并且消息 ID 与此前观察到的对方标识做完整规范化相等匹配。没有编辑距离纠错，也不允许前缀匹配，例如 `Vis` 不能匹配 `Visitor`。双方标识相同、标识缺失/低置信度/不匹配时，不用“第一条消息”强行定对方。

- “对方先、我方后”来自用户本轮人工复核的 Champions UI 约定，作为版本化辅助证据记录。它不是官方规则或任意录像的先验。只有预览到开场的受限序列有效；已经出现战斗操作、可靠战斗菜单、自身先出现或缺失首条时，不把后来的双派出自动当作首发。我方无 ID 的“上吧！”格式仍提供直接的己方证据，顺序辅助只有在此前对方匹配成功时成立。

- 对方两只宝可梦保留消息中的先后顺序，再按已建立的屏幕 HUD 逻辑规则映射：第一只右、第二只左。匹配训练家只确认所属方，不会把未知昵称变成物种、补造属性或认定持久个体。
