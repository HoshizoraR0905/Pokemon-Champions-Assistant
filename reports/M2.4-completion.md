# M2.4 — Dual identity modes and measured phase profiling

**Implementation, validation and Battle 9 profiling are complete for review.** This is not full semantic acceptance of Battle 9 or a claim of general recognition accuracy. No M3 work, Battle 8 repair, staging, commit, push, cache deletion, original-video edit or historical-report replacement occurred.

## Production behavior and commands

[CLI and policy documentation](../docs/identity-modes-m24.md) gives exact fresh and cache-reuse commands. `--profile event-driven --identity-mode lightweight` is the new event-driven default. `development` adds independent bounded verification. Detailed acquisition profiling uses `scripts/profile_production.py`; `scripts/report_m24.py` exports the chronological reports.

Both modes share the maintained StateEngine, four logical slots, message parser and active-entry episodes. Strict message naming uses canonical identities and the existing pinned/licensed 52Poké verified-title vocabulary. Complete original text and detected title assertions persist in new event records. Unsupported names, undistinguished forms and unresolved placement remain unknown. Arrival and species-resolution timestamps are separate; species equality does not merge party individuals across episodes.

Lightweight reads HP/percentages and supported non-identity/status evidence without active HUD name OCR or icon identification. Team acquisition remains separate. W control detection is retained; identity capture/reconciliation is gated out of both message modes. Development freezes message predictions before its single first-eligible post-entry HUD attempt, bypasses nickname/roster context during classification, saves original recognition/source provenance, and never feeds verification into state. Unplaced or departed episodes without an opportunity report `not_observed`. There is no unlimited retry or automatic mismatch correction. Older HUD code/models remain available.

## Final measured comparison

The 444.25-second Battle 9 recording was processed sequentially with identical final runtime-source fingerprints and the same explicitly supplied sealed pixel-prediction cache (`m24-development-v2`). Each final run used new processes and fresh decoding. These are **warm prediction-cache measurements**, not fresh inference benchmarks. OS cache warmth is uncontrolled; this is one pair with instrumentation overhead, not a statistical speedup estimate.

| Measurement | Lightweight | Development |
|---|---:|---:|
| Monotonic profiled child wall | 136.72 s | 142.40 s |
| Parent process envelope | 140.75 s | 145.78 s |
| Sampled peak process-tree RSS | 474.09 MiB | 704.88 MiB |
| Message species / supported arrivals | 8 / 8 | 8 / 8 |
| Active identity name OCR reads | 0 | 6 |
| Active identity icon adapter reads | 0 | 6 |
| Actual new OCR/icon inferences | 0 / 0 | 0 / 0 |
| Independent HUD outcomes | disabled | 6 match; 2 not observed |
| Source decoded / sampled candidates / inspected | 15,814 / 889 / 754 | 15,814 / 889 / 754 |
| Event records, including 527 HUD HP observations | 593 | 593 |

The species-coverage denominator is the eight automatically emitted send-out members; it does not measure recall for missed or unparsed announcements. The measured child-wall difference is 5.68 seconds; parent envelopes differ by 5.03 seconds. Parent timing includes process startup/monitoring and up to five seconds of exit polling. Cache-hit reads are counted separately from actual model inference; cached `latency_ms` values are never used as current processing time.

After normalizing run-directory components, **event predictions, event IDs, final Battle State and structured replay records agree**. Raw observations retain mode-specific metadata. Raw replay hashes differ because they were calculated before normalizing run-specific evidence paths; the comparison retains that raw difference and separately checks complete structured replay with only opaque `state_hash` fields excluded. No species, timestamps, values, bindings or provenance other than run-directory components are normalized.

Preliminary fresh-cache v2 runs are preserved: lightweight 216.30 seconds / 2,397 OCR inferences (124.57 seconds) / 12 icon profile matches (4.31 seconds); development 241.32 seconds / 2,403 OCR inferences (126.02 seconds) / 24 icon profile matches (9.42 seconds). All lightweight icon matches were separate roster acquisition. Those runs precede the final explicit event-title persistence; their verifier source snapshots also differ by a title-freeze fix, so they are diagnostic sensitivity measurements rather than the final same-source comparison. Their only observed underlying-state differences were roster icon latency metadata. The earlier `m24-lightweight-v1` diagnostic is also preserved.
