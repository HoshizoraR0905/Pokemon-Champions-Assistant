# Champions stat construction validation

Implemented `knowledge/champions_stats.py` as an offline utility separate from the
damage engine. It uses existing KnowledgeBase base stats and exact canonical form
identities, preserves their source provenance, and pins the encyclopedia rules in
`knowledge/data/champions_stat_rules.json`.

The API calculates full specified builds, projects exact attainable integer sets
with min/max/gaps, validates/enumerates bounded training allocations, reverses a
single actual stat to point/factor alternatives, and jointly reverses partial or
full actual-stat observations under explicit alignment/domain alternatives.
Arithmetic uses integer numerators 9/10/11 over 10 and floors once. All six training
allocations share the 66-point budget; non-neutral alignments have one increased
and one distinct decreased non-HP stat. Unknown adjustments are never neutralized.

Independent fixtures pin Charizard (revision 2627146: base, Mega X and Mega Y) and
Sneasler (2575062). All **24** published Champions ranges and corresponding base
stats match. Values come from the rendered `StatPoint` columns, not reconstructed
expected answers or interactive clicks. The optional snapshot check verified all
five cached article hashes/revision IDs and reread both species tables offline.
Rules reference 能力 2607357, 性格 2568467 and Pokémon Champions 2628728, retrieved
2026-10-15. Source-derived records retain attribution and CC BY-NC-SA 3.0 notices.

An exact example: Charizard Attack is `{93, 94, …, 141, 143, …, 149}` across all
three allowed factors and 0..32 points. **142 is absent**. Attack 149 requires
32 points and factor 1.1. With HP=2, Attack=32, Speed=32 points, increased Attack
and decreased Special Attack, the actual stat vector is
`HP 155 / Attack 149 / Defense 98 / Sp. Attack 116 / Sp. Defense 105 / Speed 152`.
Two separately attainable boosted maxima cannot be combined if both need the
single increased stat. Similarly, three 32-point investments violate the budget.
Tests explicitly reject these combinations.

Validation commands and results:

- `.venv/bin/python -m pytest -q tests/test_champions_stats.py tests/test_damage.py`:
  **475 passed** (58 stat utility tests, 417 existing forward tests).
- `.venv/bin/python scripts/validate_champions_stats.py --snapshots`:
  **24 ranges matched; 5 pinned snapshots checked**.
- Existing forward fixture/schema validation: **371 exact roll matches**, two
  expected unsupported cases and **373 schema pairs**; historical oracle fixture
  checksums remain valid.
- Stat, knowledge-grounding and artifact-policy checks with
  `-k 'not cached_full_battle'`: **87 passed, 2 deselected**. An initial broader
  run reached cached full-battle checks and was interrupted (77 passed); the
  scoped rerun excludes those unnecessary checks.

The utility does not change forward formula code, forward distributions, historical
oracle fixtures, recognition artifacts, or the knowledge identity database.
M3.1 still accepts actual stats directly. The inverse damage solver remains separate
work; it can later opt into an explicit candidate set from this utility. No video,
OCR, historical artifact rewrites, commit or push was performed.

Community documentation is distinguished from official verification. The utility
models numerical alignments, not selectable nature labels (four neutral labels
cannot be selected according to the pinned article). Fixed-HP exception species
are blocked pending Champions-specific verification; battle modifiers and roster
legality are not inferred. Enumeration requires bounded domains and rejects excess
work instead of returning incomplete sets. Article revisions do not freeze
transcluded templates, so rendered snapshot hashes are also pinned.
