# M3.1 — standalone forward damage implementation and validation

Date: 2026-10-15. **Supported reference subset implemented; unrestricted M3.1 mechanics acceptance remains incomplete.** No OCR, video decoding, multi-battle reconstruction, M2.3.4, Bayesian inference, strategy logic, commit or push.

## Result

The new offline Python API and JSON CLI calculate full discrete integer damage distributions from explicit Pokémon identities/forms, actual unmodified stats, stages, ability/item/status and field inputs. Runtime depends on Python's standard library and the existing local knowledge package. It never reads video states, recognition caches or runtime network data.

The independent oracle suite contains **373 cases: 371 supported cases match every damage roll; two deliberately return unsupported**. This includes both full-roll examples from the supplied 52poke article, which independently corroborate half-down rounding. It does not establish official Champions formula conformance.

- `champions-evidence-only-v1`: no numerical output until independently verified Champions formula/rounding evidence is pinned.
- `showdown-champions-reference-v1`: exact arithmetic under the pinned, explicitly provisional **Champions** reference implementation, not an assumed Gen 9 substitute. Successful status is `exact_reference`, never unqualified Champions-exact.

[The versioned contract](../docs/damage-v1.md) specifies fields, source pins, limitations, complete coverage boundaries and reproduction commands. The input/output JSON Schemas are `damage/schemas/{request,response}-v1.json`.

## M3.1-A — data, sources and schemas

Reused `KnowledgeBase`, its Chinese/English aliases, canonical species/form/move/item/ability IDs, identity index and pinned Champions catalog. Bare numeric IDs are rejected. Canonical `pokeapi:pokemon:*` variants use the existing identity mapping; multiple form rows require explicit disambiguation. A bare species requires an explicit base/specific form rather than a guessed current form.

A canonical-ID metadata supplement joins **344 species/forms and 525 moves** to `@smogon/calc@0.12.0`, Champions generation **0**. It is not a second identity/name database. Three local species/form entries lack a unique reference join and remain unsupported; no old-form fallback is used. All mapped type records agree with the local catalog. Base stats are metadata, never substitutes for supplied combat stats. Type or ordinary move-definition disagreements block calculation; fixed-damage catalog power sentinels have explicit dedicated handling.

## M3.1-B — integer core

Implemented integer staged stats, fixed-point modifier chaining, effective offense/defense, base formula, spread/weather/critical order, the 16 random factors, STAB, effectiveness, burn and final modifiers. Half-down rounding, floors and reference overflow points are separate operations. Trace records expose effective stats, base sequence and per-roll intermediates. Neutral STAB avoids an unnecessary overflow-producing multiplication.

The engine preserves duplicate rolls and returns integer frequencies, rational probabilities, min/max, rational percentages of maximum HP, and KO probability conditional on supplied current HP and this modeled connecting hit. Potential damage is uncapped; `hp_loss_rolls` separately caps at actual current HP. Damage results do not include accuracy, random critical chance, recoil/healing or later secondary effects.

Immunity and Seismic Toss/Night Shade are deterministic outcomes, not a fabricated 16-roll random process. Variable-power and multi-hit cases without a dedicated handler return unsupported rather than ordinary base-power results. Facade, Body Press, Psyshock and Sacred Sword have explicit exceptions.

Supplied stats must be actual **unmodified** numbers. Effective/preboosted stats are rejected to prevent double application. No stat-construction helper or guessed training distribution exists. Unknown relevant stages block exact calculation; unused stats/stages can remain unknown. Sacred Sword proves defensive stages irrelevant and can accept their unknown value. Missing maximum/current HP omits percentages/KO unless an HP-dependent ability needs it. Explicitly unknown weather, screens, abilities and items never become neutral defaults.

## M3.1-C — supported modifiers and interfaces

Bounded allowlists cover **69 audited direct-damage moves plus two fixed-damage moves**, 23 attacker-role abilities, 18 defender-role abilities, 43 item names and matching current-form Mega stones, in addition to explicit absence.

Covered reference mechanics include STAB/Adaptability; static type effectiveness/immunity; positive/negative stages; burn/Guts/Facade; sun/rain; sand Rock special defense and snow Ice defense; all four terrain effects within the supported move set; critical stage bypass/prevention/Sniper; Reflect, Light Screen and Aurora Veil without stacking; doubles spread; Helping Hand/Friend Guard; audited offensive/stat/defensive/absorption abilities; Normal-type conversions; relevant damage items/resistance berries; and current Mega form typing with caller-supplied actual stats.

Python API: `damage.calculate(request)` and `damage.calculate_scenarios(request)`. CLI: `python -m damage [input.json]` or installed `champions-damage`. JSON stdin is supported; non-finite input numbers are rejected. Conditional scenarios are fully caller-specified and individually diagnosed, with no automatic builds, weights or Bayesian probabilities.

The source contract lists the complete boundary. It intentionally rejects unsupported abilities/items, transformed/type-overridden states, Tera/Dynamax/Z mechanics, grounding overrides, unresolved protection/substitute/field interactions, multi-hit joint distributions and between-hit effects, unaudited variable-power moves, Foul Play, Knock Off and Electro Shot's pre-hit boost. Doubles spread with only one remaining target needs a dedicated oracle case. Galvanize and Storm Drain remain unsupported because pinned Champions behavior differs from familiar Gen 9 assumptions; no expected oracle output was rewritten to hide that discrepancy.

Current form is an input, not an automatically applied evolution event. Explicit actual stats take precedence over every base-stat table. Unknown/conflicting/absent/unsupported states have distinct diagnostics. The engine reports the first blocking issue rather than claiming an exhaustive missing-field list.

| Suite | Result |
| --- | --- |
| Curated oracle cases | 93/93 supported full distributions; 2/2 explicit unsupported diagnostics |
| Mixed stages/weather/screens/items/abilities | 160/160 full distributions |
| Terrain combinations, low-HP abilities, integer overflow | 118/118 full distributions |
| Total supported oracle parity | **371/371** |

| Integrated damage/historical-state regression run | **549 passed** in 153.55s |
| Final focused damage suite after targeted refinements | **417 passed**; overlaps the integrated run, not additive |

The pinned Node adapter independently calculates expected rolls. It explicitly overwrites constructor stats, HP, level, ability, item, status and stages, then invokes the unmodified Champions mechanics function. This avoids its default native ability, forced level 50, or public wrapper clone deriving different stats. Constructor EV/nature description strings are cosmetic oracle descriptions; actual combat stats enter directly. Fixture inputs and oracle rolls are separate pinned files, including npm integrity and transitive versions. All three fixture groups were regenerated to separate cache files and compared byte-for-byte without changing expected results.

Coverage includes neutral physical/special, STAB, weakness/resistance/immunity, all stages −6..+6, burn, weather/terrain, screens, criticals, doubles spread, items/abilities, old/new Mega forms, dedicated exceptions, rounding ties and overflow. The two 52poke examples match all sixteen listed outcomes, not only extrema. Invalid ranges/types, unknown/conflicting conditions, unsupported exceptions, form mismatches, unknown HP/KO behavior, explicit scenarios, caller immutability, canonical mappings, offline imports and CLI JSON/exit status have regressions.

Two intentionally extreme input cases initially exposed missing stage-overflow placement and an unnecessary neutral-STAB multiplication. The implementation was corrected against unchanged oracle outputs, and those full distributions remain pinned regressions. The final ordinary and combined-modifier cases all match. No expectations were adjusted to make Python results pass.

No fully specified Champions gameplay damage sample with independently known combat stats and all modifiers was established from existing evidence. The prior C footage does not expose those inputs, so numerical Champions gameplay conformance remains **unmeasured**, not a pass. Existing historical Swords Dance +2, known moves, forms, explicit continuity and correction/retraction regressions passed without altering tracker code or rebuilding multi-battle reports.

Packaging: a wheel built with isolated `setuptools==75.8.2` and `wheel==0.45.1`; data and schemas were checked against source, and a `python -S` wheel import calculated damage without OCR/site-package dependencies. The first build attempt found missing legacy wheel tooling; production environments were not upgraded. Optional schema tooling is isolated and pinned (`jsonschema==4.25.1` plus its recorded dependency versions). The calculator itself needs neither Node nor jsonschema.

## Gaps and integration readiness

This is a working, independently testable exact **reference subset**, not complete Champions damage acceptance. Remaining work includes verified Champions formula/rounding evidence, broader special/variable/multi-hit mechanics, additional abilities/items/interactions and explicitly validated single-remaining-target spread behavior. Unsupported cases produce no fabricated numerical output.

The API is ready for explicit manual/validated snapshots within its declared reference domain. It is not ready to trust automatic M2.3.x recognition as complete damage inputs. A future M2.3.4 adapter must validate form, actual stat convention, freshness/instance identity, every relevant modifier and unknown/conflict status before calling it. M2.3.4 and recognition integration were not started.
