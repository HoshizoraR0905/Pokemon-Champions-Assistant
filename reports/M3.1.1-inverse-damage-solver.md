# M3.1.1 — Constraint-based inverse damage solver

Date: 2026-10-15. **Implemented and validated within M3.1's supported provisional
reference subset.** Unrestricted M3.1 mechanics and official Champions formula
verification remain open. No recognition, video processing, M2.3.4, Bayesian
inference, strategy work, commit or push was performed.

## Model and behavior

For each supplied actual unmodified Attack or Special Attack candidate A and
explicit finite assignment z, calculate all supported M3.1 raw damage rolls.
Observation i retains A exactly when those rolls intersect its justified exact,
interval or discrete direct-damage constraint. The joint answer is
`union_z intersection_i S_i(z)`. There is no duplicate damage formula or algebraic
approximation. Stage changes remain specific to each observation.

Shared variables receive one value across all their observations; local variables
vary independently. Persistent unknown items cannot change just to satisfy each
hit. Every scenario's exact set, matching/supported rolls and dependencies remain
available. If any needed branch is unresolved or unsupported, the complete answer
is null with diagnostics, rather than a union that silently omits that branch.

Observations require battle, attacker/target instance IDs, a stat epoch, a complete
forward context and explicit direct-damage evidence. Different instances, forms,
levels or epochs require evidenced continuity of the **unchanged numerical stat**.
A total HP decrease is not accepted automatically as direct damage; caller evidence
must address residual effects, recovery and KO censoring. The designated unknown
stat replaces its forward-template entry; the candidate domain is explicit.

Forward-handler dependencies come from the existing successful calculation trace
through a small new `stat_dependencies` interface. No forward arithmetic changed.
Body Press, Psyshock, fixed damage and immunity are tested; absent dependencies
are marked non-informative. Unsupported exceptional moves remain unsupported.
Attack and Special Attack are separate variables.

Empty sets retain every observation and report marginal feasibility plus a
conflicting subset. Deletion minimization reuses calculated sets and is bounded;
when its work budget stops early, the subset is labeled explanatory rather than
minimal. Results distinguish unsupported mechanics from missing/conflicting inputs.
No domain/evidence widening, hidden priors or inferred build configurations occur.

## Performance and recovery

Measured locally with exactly 200 candidates; machine-specific elapsed times:

| Workload | Forward evaluations | Assignments | Time |
| --- | ---: | ---: | ---: |
| One observation | 200 | 1 | 17.1 ms |
| Three observations sharing a stat | 600 | 1 | 52.0 ms |
| Two observations, one shared uncertain screen | 800 | 2 | 69.3 ms |

Equivalent full requests are memoized per solve, and forward static data uses the
existing cache. Tests verify repeated requests hit the memo. Default bounds are
4096 candidates, 128 assignments, 100000 conservative forward evaluations and 128
conflict checks, all configurable. Over-budget requests return diagnostics before
enumeration; there is no silent truncation.

```sh
.venv/bin/python -m pytest -q tests/test_inverse_damage.py tests/test_damage.py tests/test_champions_stats.py tests/test_git_artifact_policy.py
.venv/bin/python scripts/validate_inverse_damage.py --schema-library .cache/m31/schema-lib
```

The validator runs offline using saved fixtures, prints progress, atomically
checkpoints successful stages, and pins code/schema/data/fixture fingerprints.
Changed versions retain separate checkpoint files. Repeating the command reuses
valid completed stages. `.cache/m311/latest-validation.json` identifies the latest
completed manifest, currently `.cache/m311/validation-2c82ce906cd9.json`.
Failed runs preserve successful stages and write an error record. Oracle fixture
generation is a separate explicit command, never a runtime/test dependency.

## Limits and future integration

`exact` means exact enumeration under the specified reference model; it is not a
claim of official Champions formula correctness. The conservative evidence-only
profile remains numerically unsupported. Unsupported forward mechanics cannot
become supported through inversion. Identity continuity and damage attribution are
caller evidence assertions, not independently verified facts.

The solver accepts a supplied numerical domain, not a universal claim of species
legality. Correlation beyond the supported shared/local variable model requires
separate explicit correlated assignments/solves. Candidate search and output are
bounded and in-memory; durable process recovery is provided for the validation
harness. No unbounded build search is attempted.

Future battle-state integration should provide evidence-backed instance IDs,
stat epochs, quantitative stages and direct-damage constraints through this API.
That integration and subsequent milestones remain outside this implementation.
