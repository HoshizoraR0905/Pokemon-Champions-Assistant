# M3.2 — Speed order constraint solver

Date: 2026-10-15. **Supported reference subset implemented and validated.** The
standalone `speed_order` package provides an effective-Speed evaluator, exact
inverse constraints, a read-only comparison API, JSON CLI and versioned schemas.
It does not perform recognition, recommend moves or assign build probabilities.

### Discovered reference discrepancy

The independent tests exposed a cap discrepancy: calc's `getFinalSpeed` treats
Champions generation 0 as <=2 at its final cap, yielding **999**, whereas the pinned
simulator permits **10000**. The implementation therefore returns **unsupported
when uncapped effective Speed exceeds 999**. It does not choose one result silently.

All original calc expected values remain recorded. A modern-generation utility
probe identifies cap-disagreement cases only; it is not a Champions fallback or
expected answer. Of 1638 reference rows, **1353 match exactly** and **285 are
explicitly gated** because of that discrepancy. High-Speed support remains open
pending independent validation of the intended Champions behavior. This limitation
can affect legitimate strongly boosted Speed combinations.

## Supported behavior and boundaries

| Mechanic | Handling |
| --- | --- |
| Actual Speed and stages -6..6 | Exact stage floor through existing integer helper; actual domain 1..4095 avoids reference/simulator overflow disagreement |
| Tailwind | ×2, explicit state at order decision |
| Swift Swim / Chlorophyll / Sand Rush / Slush Rush | ×2 under explicit rain/sun/sand/snow, otherwise inactive |
| Unburden | Explicit active/inactive history required; item absence alone never triggers it |
| Speed Boost | Supplied resulting stage only; no extra permanent multiplier |
| Choice Scarf / Iron Ball | ×1.5 / ×0.5 in the audited subset |
| Quick Feet / Surge Surfer | Explicit status/terrain conditions |
| Paralysis | Floor-halving after chained modifiers, except Quick Feet |
| Equal effective Speed | Either observed order remains feasible; no tie probabilities |
| Trick Room | Reverse numerical ordering; no standard underflow substitution |
| Audited ordinary move priorities | Supplied effective priority must agree with pinned Champions catalog |
| Prankster / Gale Wings / Triage | Explicitly unsupported priority handlers |
| Grassy Glide and other conditional/special actions | Gated outside the closed audited move list |
| Quick Claw / Custap / late-order items / Stall | Presence alone unsupported; evidenced active ordering effects are non-Speed and not numerically inverted |
| After You / Quash / forced actions | Non-Speed/non-informative with explicit evidence; no guessed interactions |
| Mid-turn recalculation | Unverified; ambiguous modifier changes or wrong-time snapshots yield no Speed inequality |

Modifiers are chained with fixed-point integer arithmetic and half-down rounding;
paralysis is applied afterward. Only the bounded audited subset is claimed.
Unsupported abilities/items/effects do not become neutral defaults.

## Observation and inference model

A structured observation contains battle and stable instance IDs, canonical current
forms, a stat epoch, ordered action sequence, move/effective-priority evidence,
turn and order-decision identity, complete participant/field modifier snapshots,
explicit absence or evidence of ordering effects, and comparability/source labels.

Only established ordinary move comparisons at one ordering decision are informative.
Animation timestamps, switches, inability/fainting, entering mid-turn, repeated
or multi-action mechanisms are not inequalities. Later weather, Tailwind, stage
or item snapshots are never applied retroactively. Different turns can supply
different evidenced snapshots while retaining one underlying Speed. Different
instances, forms, battles or stat epochs cannot be merged solely by species.

For each candidate S and finite assignment z, evaluate both effective Speeds.
Outside Trick Room, opponent-first permits `V_opp >= V_own`; inside it permits
`V_opp <= V_own`. Opponent-second reverses the inequality. Equality remains feasible.
The solver returns `union_z intersection_i S_i(z)`, retaining exact integers,
gaps/hulls, per-observation compatible effective values, ties and all assignments.
It never intersects marginal unions of incompatible shared assignments.

Unknown item/ability/Tailwind/weather/stage/paralysis/Trick Room state requires
explicit finite alternatives. Variables are shared or observation-specific;
independent persistent item/ability changes across observations additionally require
`change_evidence`. Unsupported/unresolved branches leave the complete answer null.
No scenario is dropped just to permit a guaranteed claim.

Non-informative observations retain the full candidate domain with reasons.
Contradictions with an audited priority winner are explicitly marked rather than
converted into Speed constraints. Empty numerical sets produce conflict subsets,
with deletion minimization limited to 128 observations and nonminimal results
labeled. An already-empty legal domain is diagnosed separately.

## Legal Speed and examples

`champions={identity, form, ...}` reuses M3.1.2's exact Speed domain and compact
joint training configuration representation. Known point/adjustment/other-stat
restrictions share the same 66-point budget. Legal-domain gaps remain intact.
An explicit numerical domain is also accepted; its order-feasible set is retained
separately from the final legal intersection. No nature or preferred investment is
selected implicitly.

| Example | Result |
| --- | --- |
| Opponent first, own effective Speed 100, candidates 50..249 | **100..249**, includes tie 100 |
| Opponent second, same context | **50..100**, includes tie 100 |
| Opponent first under Trick Room | **50..100** |
| First comparison requires S>=100; later own Speed 180, opponent +1 stage, own first | **100..120** |
| S=100, opponent first against 140 and second against 110, one unknown persistent Scarf | **Empty**: each is individually feasible under incompatible item choices |
| Same comparisons with evidenced independent item changes | **{100}**, consistent local assignments retained |
| Neutral Charizard Speed with 32 HP and 32 Attack points | **{120,121,122}**, only two points remain |

Examples are synthetic explicit-state inputs, not automatically extracted evidence.

## Decision-facing API

`compare_speed` is read-only and quantifies over every supplied candidate and
scenario. It returns one of the seven required decision statuses, plus explanation,
guarantee booleans, tie information and detailed comparisons.

- Own Speed 100 vs candidate 99: `own_guaranteed_first`.
- Versus 101: `opponent_guaranteed_first`.
- Versus 99/101: `mixed_order_possible`.
- Versus 99/100: `speed_tie_possible`, with tie-only uncertainty.
- Versus 99/100/101: tie possible **and** non-tie order variation, explicitly distinguished.
- Higher audited move priority: `non_speed_ordering`, with the priority winner.
- Unsupported/unresolved branches: no guaranteed-first flag.

Forced-order interactions are not numerically guessed. No statistical confidence
or move recommendation accompanies any result.

## Interfaces and validation

Python exports are `effective_speed`, `infer_speed` and `compare_speed` from
`speed_order`. JSON command:

```sh
.venv/bin/python -m speed_order examples/speed_order/infer.json
.venv/bin/python -m speed_order examples/speed_order/compare.json
```

Installed entry point is `champions-speed-order`. Schemas are in
`speed_order/schemas/`. The detailed [API and evidence contract](../docs/speed-order-v1.md)
documents required context fields, limits and source qualifications.

The independent Node fixture adapter executes the pinned Speed utility directly
and the actual Champions `getActionSpeed` method with oracle speeds. It verifies
package file hashes, supplies explicit raw stats/activation flags, and does not
import Python Speed code. Normal tests need only saved fixtures.

Validation commands:

```sh
.venv/bin/python -m pytest -q tests/test_speed_order.py tests/test_champions_feasibility.py tests/test_champions_stats.py tests/test_inverse_damage.py tests/test_damage.py tests/test_git_artifact_policy.py
.venv/bin/python scripts/validate_speed_order.py --schema-library .cache/m31/schema-lib
```

Latest completed suite: **1018 passed** (64 Speed tests plus all 954 preceding
stat/forward/inverse/integration/artifact tests). Independent fixtures comprise
**18 groups / 1638 rows: 1353 exact matches, 285 explicit cap-discrepancy gates**.
Schema checks cover **1646 request/response pairs**, including examples and
empty/unsupported/unresolved/non-informative inference responses; invalid request
shape rejection is also checked. Selected Trick Room/tie ordering cases execute
the pinned Champions action-speed method; high-cap cases are gated rather than
claimed as numerical parity.

Tests cover the requested ordinary/priority/exception, stage/weather/terrain,
activation, timing, shared/local, empty-set, legal-domain, identity, unknown-state,
determinism, cache-mutation and runtime-isolation cases. Unsupported expectations
remain explicit. Existing damage oracle values are unchanged.

## Performance and recovery

Measured locally, not a real-time guarantee:

| Workload | Evaluations | Elapsed |
| --- | ---: | ---: |
| One observation, 200 candidates | 200 | about 12 ms |
| Two turns, 200 candidates | 400 | about 23 ms |
| Two turns and two shared item alternatives | 800 | about 46 ms |
| 100 repeated comparison queries, three candidates each | 100 queries | about 17 ms total / 0.17 ms per query |

Default limits are 4096 candidate entries, 128 assignments and 100000 conservative
evaluations. Work is deterministic and bounded. Identity/effective-Speed caches
are process-local and bounded; outputs are copied to prevent mutation of cached
results. Identical per-solve comparisons are memoized.

The validator atomically checkpoints each completed stage under `.cache/m32/`,
prints progress, and fingerprints Speed code/schemas/fixtures/data and relevant
shared stat/integer dependencies. Repeating the same command reuses valid stages;
older fingerprints and successful stages are preserved. Failed stages record an
error. The latest completed manifest is located through
`.cache/m32/latest-validation.json`. Optional fixture rebuilding is separate:
`scripts/build_speed_fixtures.py`; inference and validation do not require Node.

## Preservation and remaining integration

Prior M3.1.2 files match their saved hashes. Existing tracked implementations,
source pins and damage fixtures are unchanged; the only previously tracked file
changed is `pyproject.toml` for package data/discovery and the CLI entry point.
No OCR, video decoding, M2.3.x changes, speed-order recognition, Bayesian priors,
strategy integration, commit or push occurred.

Future battle-state integration must establish source-backed action comparability,
priority/trigger state, activation history and order-decision snapshots before
calling this solver. High-Speed cap validation, priority-changing abilities,
additional action exceptions and Champions mid-turn recalculation remain open.
This milestone does not authorize later implementation work.
