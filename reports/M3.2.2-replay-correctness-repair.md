## Root causes and repairs

**Wrong unresolved Raichu name:** `renderOpponents` chose the first
`possible_forms` entry when `current_form` was null; the sorted list began with
Alolan Raichu. The export also lacked an explicit canonical species field for
that fallback. The repaired snapshot exports `species=pokeapi:species:26`, keeps
`current_form=null` until confirmation, and the browser labels it **雷丘 · 当前形态未定**.
Possible canonical forms are listed separately. Labels come from the existing
KnowledgeBase; no alternative name/form dictionary was created.

**Lost Mega:** the source was not missed by OCR. Source event
`event:64f3c610af2085dc041a4b15` at **158.026667s** contains the Mega transformation
message. The parser had `attributes.identity=null` and
`transformation_identity_unknown`; the ledger had `instance_id=null`, deferred
application and no state snapshot for this event. M3.4's original assignment was
unassigned, and M3.4.1 preserved it as a non-move observation. Stage A retained the
generic transformation in its raw timeline, but the browser's known-action table
only included moves and a short list of explicitly attached review events. The
later Garchomp Mega was attached manually, explaining the inconsistent display.

Two original frames resolve Raichu's target form independently:

- **148.525s, frame 000265:** explicit 雷丘进化石Y reaction text, with base Raichu
  visible. The OCR/event cache already retained it as
  `event:a846f6e9012f242c1029fffa`, classified as `move_effect` with no item reference.
- **158.026667s, frame 000284:** transformation announcement and resulting Mega
  Raichu Y silhouette. The existing pinned `raichu-mega-y.png` asset corroborates
  the visual identity. Animation frames 000271/000277/000283 were also inspected.

A reviewed item revelation now becomes available at 148.525s. A separate
`mega_evolution` event binds the original stable Raichu encounter
`sample_battle_11:opponent:encounter:3a97ce2b12c2c2fe`, from canonical base
`pokeapi:species:26` to **`pokeapi:form:10530`**. Its conservative uncertainty
interval is **[148.525, 158.026667]s**. The current form is applied at the upper
confirmation bound; exact animation-completion timing is not invented. Earlier
snapshots do not inherit the later form. On the reviewed return, the source
encounter ID is retained as an evidence-timed alias of the original individual.
The opponent's unique Raichu/Volcarona/Incineroar roster is visible in original
Battle 11 roster frame 000042; return messages provide the later link evidence.

**Missing switches/pivots:** the raw recall/send-out events already existed, but
were not normalized into transactions or included in the known-action table.
The new derived projection pairs explicit messages and checks phase context. It
uses original event IDs, frame hashes, side, source individuals, departure/arrival
times and existing segment intervals. A HUD species change alone never admits a
voluntary switch. Pivot classification additionally requires its own preceding
supported pivot move and explicit return wording. Failed pivots do not generate
replacements. Unpaired or conflicting evidence produces an explicit unresolved
transition instead of silently disappearing.

The reported **Volcarona → Incineroar** transaction is recall **210.001667s**,

## Two support layers and causal behavior

The current presentation separates two kinds of support:

1. **Observed joint builds:** only complete eligible records from the existing
   `vgcmulticalc / tournament_published / M-C / Doubles` corpus, filtered by the
   evidence available at the selected time. Source/build IDs point to the original
   joint item, ability, alignment/nature, training points and Speed SP records.
   Complete counts before/after and incomplete exclusions are shown. Missing
   fields are not filled, and dataset absence is not illegality.
2. **Full reference model:** retain the non-neutral item alternatives, correlations,
   exact discrete stat sets and joint training-domain references. Unsupported native
   ability branches and uncertified action-time modifiers remain explicitly
   unresolved. This is not independent Champions mechanics certification.

Full branch tables and joint alignment/Speed-SP records are expandable, with lazy
rendering. The default card contains two compact summaries. Empty computed sets
are distinguished from unknown results, and gaps are displayed as separate
intervals/singletons rather than filled continuous ranges.

At B11 **200s**, Volcarona renders these values from stored solver projections:

| Layer | Surviving unmodified Speed |
| --- | --- |
| Observed builds, 33 → 29; 48 incomplete records excluded | [120–125] ∪ {128,130,137,144} ∪ [150–151] |
| Full reference model | [108–152] ∪ [154–163] ∪ [165–167] |

The browser assertions compare the rendered full-reference set with the exported support
rather than embedding those values in the UI. Existing conditional constraint
results are retained with their inherited assumptions; this repair adds no new
quantitative Speed inequality from the newly classified switches/Megas.

Mega training is recomputed with existing `configuration_domain` and M3.2.1
`training_stats`. Required original stones, alignment/SP domains and original
ability alternatives remain correlated with transformed configurations; the native
resulting ability is projected separately from an observed activation. Mega Raichu
Y therefore has its own form-specific stat projection, required Raichunite Y and
native No Guard hypothesis. No Guard remains outside the audited order-handler
subset: its current form is known, while its exhaustive order handling is explicitly
unresolved. No new mechanics engine was introduced.

Snapshots retain only evidence available at/before the cutoff. Before an arrival,
the transaction's incoming identity, arrival source ID and completion time are
hidden. Reviewed encounter aliases are applied only at their source time.
Backward/forward seeking restores form, item visibility, occupants, and support
sets. The pre-revelation Raichu stat projection is checked against the sealed Stage
A snapshot. Switches, Mega transformations and moves retain separate phases and
source chronology; pivot/faint replacements do not enter the voluntary phase.
