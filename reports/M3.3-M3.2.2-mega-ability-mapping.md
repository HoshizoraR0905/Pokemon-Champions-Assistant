# M3.3 / M3.2.2 — Mega ability mapping repair

The empirical adapter incorrectly rejected legal original abilities recorded on
published Mega-form builds. Mega Raichu Y now admits **68 complete member records
across 51 distinct joint Pokémon build IDs**, rather than 3 records across one
build ID. All 68 remain Timid-like (+Speed / −Attack); no complete Mega Y records
remain excluded. Twelve incomplete records remain outside exact build support.

## Provenance and implementation trace

1. `metagame/published/speed_support.py:SpeedSupportIndex.load` reads the existing
   published-team database in read-only mode. It preserves canonical member
   identity, recorded ability, nature/alignment, full SP, item, moves, Pokémon
   build ID, observed team signature and publication provenance. A source Mega
   identity supplies its reference stat form; it does not certify when that
   form or ability became active in a battle.
2. `battle_evidence/speed_reviewed.py:empirical_configs` previously compared that
   ability directly with the current form's native ability list. This rejected
   65 Lightning Rod records. Empirical builds do not pass through
   `configuration_domain`; this parallel native-ability check was the bug.
3. `speed_order/forms.py:published_ability` now separates source ability,
   original form/ability and current active ability. Original abilities are
   checked against the canonical pre-Mega form; after transformation the sole
   canonical Mega ability applies. Required stones and preserved joint training
   are checked independently. `training_stats` recalculates Speed for the current
   form using the same full SP allocation and alignment. No source rows or IDs
   are rewritten. The raw `observed_build` remains byte-for-field equivalent.
4. `configuration_domain` continues to require native abilities for its current
   form. The full Mega reference branch already preserved original training,
   stone and ability and applied the canonical active Mega ability. It remains
   unchanged. The fix adds no non-native active-ability whitelist.
5. `battle_evidence/speed_replay_projection.py:project` excludes unconfirmed Mega
   forms from current active-form alternatives. Before transformation, published
   eventual Mega configurations can supply their known original base ability
   and base-form Speed. Only the confirmed transformation exposes the derived
   canonical Mega active ability. Snapshot `observed_ability` stays separate
   from the new derived `active_ability`; per-member `ability_mappings` preserve
   source/original/current meanings. The UI shows both the source build and its
   current mapping.

The resolver uses existing canonical species/form relationships and native
ability/required-item facts. It also handles a unique non-base-species pre-Mega
form where present in the catalog; unresolved relationships fail explicitly.
This is general Mega handling, not a Raichu exception. The underlying native facts
remain catalog/reference assertions, not newly observed hidden battle facts.
