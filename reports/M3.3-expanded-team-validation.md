## Identities, field eligibility and source isolation

Strict Team Composition and Exact Build fingerprints remain unchanged. A one-point SP difference still produces a separate Exact Build; SP-unknown records never receive Exact Build identities. A separate versioned observed signature includes known configuration, explicit missingness, unresolved assertions and supported SP components. Its frequencies describe observed-configuration diversity, not proven unique underlying builds. Every signature retains represented source publications and links.

For each field, only eligible target observations form the denominator. Complete target moves support move and move-pair frequencies without SP/nature; known item/ability/nature independently support those distributions. Full target SP vectors need all six supported components; individual components have independent eligibility. A teammate condition requires a complete resolved roster. Unknown information is neither negative evidence nor zero. Multiple indistinguishable target instances are excluded from target-field analysis. No placement/popularity or publication-count weighting is applied.

The SQLite schema advances through append-only migrations to version 4, preserving strict identities and all historical evidence. Observed algorithm definitions are guarded separately against changes under an existing version. Source population, regulation and format remain explicit query selectors; observed statistics additionally require one source. PokeDaily retains its six Unknown-format records. Champions Battle Data Ranked marginals are neither joined into team configurations nor used as fallback data.

## Reproduce, provenance and recovery

Use the commands in [published-team designs](../docs/published-team-designs.md). `collect-details --regulation M-C` resumes the pinned repository corpus; `collect-submissions --regulation M-C` resumes authorized public submissions without another authorization prompt. Both accept `--limit 20` for a deterministic diverse pilot. Pinned M-A and M-B collection stays separately scoped.

Collection is serial with a two-second minimum interval, bounded retries, Retry-After handling, durable rate state, immutable raw blobs and atomic per-record checkpoints. Completed compatible records and HTTP receipts are reused; partial failures preserve successes. Public HTTP responses refresh after 24 hours, and changed index identities invalidate a record shortcut. Repository commit URLs remain reusable indefinitely. No raw dataset is publicly redistributed. This published-design cache retains provenance/history as requested; it does not apply that policy to the separate bounded current-Ranked API cache.

The database is `.cache/metagame/published-teams/teams.sqlite3`; run checkpoints are in `runs/`, source captures in `raw/` and `http/`, and detailed local validation outputs in `review-v3/`. To inspect source evidence for the Nice example:

```sql
SELECT p.source_key, p.source_url, c.url AS captured_url,
       c.retrieved_at, c.raw_sha256
FROM publications p
JOIN publication_captures pc ON pc.publication_id=p.id
JOIN captures c ON c.id=pc.capture_id
WHERE p.source_id='vgcmulticalc' AND p.source_key='jgJkqtHKY6';
```
