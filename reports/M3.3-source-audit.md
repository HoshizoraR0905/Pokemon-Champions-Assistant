# M3.3 source audit

Audited 2026-10-20, before ingestion implementation. Scope: ordinary-player Champions Doubles; no tournament/ladder population pooling. Local HTTP receipts and exact response hashes live in `.cache/metagame/source-audit-20261020/`. Direct Python requests verified JSON where the browsing renderer could not open it. No authentication, CAPTCHA or access controls were bypassed.

## Decision

**Primary and required target: actual Pokémon Champions in-game Ranked Battles.** Use the documented Champions Battle Data API as a third-party **claimed in-game Ranked** source. The API's use of Showdown name identifiers does not establish a Showdown sample population. Do not substitute simulator statistics in the main database.

The API permits personal/application use and reasonable caching. Implement a private, bounded **current application cache**, not an indefinite historical archive or competing public data service: configurable refresh (24 hours by default), seven-day retention, at most two retained response/parser versions per URL, source attribution, no public raw-dataset export. Cached current data can be revalidated; superseded/expired application-cache entries are pruned only within the package-owned namespace. This interpretation follows the user's clarified current-cache scope. No source-owner permission to build a permanent mirror is asserted.

Exact battle sample counts, collection method, rating eligibility and independently verified game-capture evidence remain unknown. Preserve source-reported proportions without fabricated counts or confidence intervals. This does not block the bounded application pilot.

## Official verification and mechanics

[Official Pokémon Support](https://support.pokemon.com/hc/en-us/articles/360043472332-What-is-the-Battle-Data-feature-in-Pok%C3%A9mon-HOME) documents HOME mobile Battle Data, but does not establish an open Champions statistics API. Searches did not establish an official downloadable Champions Ranked dataset. No in-game screenshots or authenticated official endpoint were available for independent comparison. Third-party statements are retained as claims.

Reuse the versioned [existing Champions stat rules](../docs/champions-stats.md), sourced from pinned 52Poké revisions; do not import generic EV formulas. The inspected Showdown stats reference includes legacy spread transformations; its 0–32-looking values alone would not certify SP. That dataset is excluded. For the primary API, use the explicit source category/column evidence described below, preserving its source-assertion qualification. Existing canonical KnowledgeBase resolves all identity facts; newly unknown forms stay unresolved.

## Additional in-game candidate

[MunchStats about](https://www.munchstats.com/about/) describes its own automated reads of in-game Battle Data. The [public implementation](https://github.com/PizzaTimeJoshua/munchstats/blob/bcb57082769716b8ad26b193c017d43944c652a0/app.py) explicitly separates that feed from Showdown. Its `champions-data` branch and published mobile packs are downloadable. A bounded inspection found capture commit `c0e71bb435cb57427dba42cd16904f3d2a596e28`, dated **2026-10-06**, with 260 indexed Pokémon; the FAQ's 235-species/nightly description and live homepage are not proof that this pack is current. The pack contains source percentages, SP vectors and teammate ranks, without independent sample counts. Static species metadata includes simulator references and must be separated from capture evidence. The site's robots file requests a ten-second crawl delay and excludes historical `?month=` crawling. No broad redistribution license was established. This is a separately labeled future comparison candidate, not the primary ingestion source; its audit bytes are not loaded into the database.

## Architecture selected after audit and scope clarification

The isolated `metagame` package stores original current API bytes, bounded HTTP receipts and a schema-versioned SQLite projection. Fetch `/api`, resolve exact canonical species/forms through the existing KnowledgeBase, then fetch only the requested current `/api/battle/Doubles/<showdownId>` endpoints. No historical-season query, simulator fallback, tournament ingestion, crawl, live battle-state inference, damage or strategy integration. The nine requested Pokémon form the current pilot; broader collection has not been performed.

The initial audit considered a Showdown archival fallback before the user clarified the required population. That option was discarded. Showdown/PokéKit audit evidence remains outside the application cache and is not a default or fallback dataset. Preliminary code was changed to enable only Champions Battle Data.

The retained cache records source type and URL, retrieval/check timestamps, unknown source publication timestamp, index generation/data version, `Current` season label, unknown regulation/game version, format, unknown rating/sampling/weighting/count/denominator, raw SHA-256 and parser/normalizer/knowledge versions. The index generation timestamp is not mislabeled as the per-species game's collection timestamp.

## Spread semantics investigation

The tested response explicitly labels the category `stat_points`, with separate `hp_points`, `attack_points`, `defense_points`, `sp_atk_points`, `sp_def_points`, `speed_points` columns. The [provider's manifest generator](https://github.com/Gheist23/pokemonbattledata/blob/main/tools/generate-manifest.mjs) declares that exact ordered column list; its row formatter/parser and [display code](https://github.com/Gheist23/pokemonbattledata/blob/main/app.js) carry those values into stat-spread displays. No EV-to-SP conversion is applied by this client. Local investigation retains the inspected code bytes/hashes. This supports **source-asserted** `champions_sp`, separately qualified from independent game validation; it does not certify the upstream extraction method.

Complete vectors are checked using the existing versioned 52Poké-based rules (0–32 per stat, at most 66 total). Incomplete components remain null; invalid vectors remain preserved and flagged, not repaired. Do not infer a full build by joining independent nature, item, ability or spread marginals. Source metadata fields named `baseStats` also resemble uninvested display stats (e.g. Pelipper HP 135); they are not imported as canonical base stats or used to compute Speed. The shared KnowledgeBase remains authoritative for canonical identities and existing maintained stat construction.
