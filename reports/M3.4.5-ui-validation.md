# M3.4.5 — Compact inference UI validation

Prepared for human review on 2026-10-23. **No independent human acceptance or recognition accuracy is claimed.** Use the short [review checklist](M3.4.5-human-review.md) for timestamps, local URLs and screenshots.

## Inspected problems and resulting presentation

The initial actual-browser inspection covered Battles 11 and 12 before move revelation, after admitted damage, after Speed-order constraints and in later turns. Baseline screenshots/receipts are in `.cache/m345/baseline/`. The initial Battle11 before-moves capture was an earlier empty introductory state; the final capture uses 158.526667s with identified Mega Raichu Y before its executed Fake Out.

The baseline Battle12 third-hit page put an inactive Incineroar before Hatterene. Repeated support counts, raw instance IDs, source-link lists, hulls beside exact sets and long diagnostics obscured the relevant result. Battle11's empirical Speed hull was prominent while the full Attack constraint and coupled Speed lower bound required expansion. The inactive-before-active ordering was particularly misleading during review.

The existing HTML/JS/CSS renderer now:

- Prioritizes active opponents and the most recent evidence within that group; preserves departed individuals in expandable cards.
- Shows current species/form, source-observed item/ability or explicit unknown, and labels a canonical Mega ability as form-derived rather than independently observed.
- Shows exact reference Speed and informative Attack/Sp. Atk projections, with explicit union notation and preserved integer gaps. It introduces no expected value, distribution or representative build for the reference set.
- Shows approximately three VGC cores with nature, three combat stats, item, ability, original occurrence multiplicity and conditional sample share. SP, templates, source IDs, score diagnostics and additional cores remain expandable.
- Separates sample exhaustion from lack of eligible observations. Both automatically show compact reference supports, without fabricating observations or resetting weights. Both-empty supports produce a contradiction/model diagnostic, qualified when policies or unresolved assumptions prevent a global conclusion.
- Separates evaluated supports, retained unresolved classes and Practical omissions. A single 100% sample core explicitly does not determine the opponent's actual configuration.
- Summarizes the latest admitted damage/Speed change using existing before/after projections. Damage mismatch and item-evidence exclusions remain separate; rank changes are not reported as eliminations. Comprehensive summaries compare evaluated projections when unresolved branches conceal narrowing of the total projection.
- Adds before/after navigation for every admitted damage and Speed-support update, original-frame links, and bookmarkable `t=` URLs. Future timeline markers reveal no move names or HP values. Inactive source details, action logs and state JSON are collapsed by default.

The two existing support layers and the original static review server remain. The small `supportView` helper classifies existing support metadata for presentation; it does not generate configurations or filter evidence. No additional inference architecture was introduced.

## Boundaries and remaining limitations

VGC source exclusivity, no-deduplication occurrence counts, alpha=.5 default, smoothing, soft move matching, hard evidence, item-policy rules, source-reviewed HP and third-hit context are unchanged. The UI version is M3.4.5; underlying sealed inference packages correctly remain M3.4.4. Earlier reports and package manifests were preserved.

Reference supports remain conditional on pinned mechanics, available state and selected policy; Comprehensive still has unresolved Air Balloon / Metronome branches. Exact projections cannot be freely combined into a new joint build. Counts are not probability mass. Unknown held items/abilities stay unknown even when a leading VGC template supplies one example.

Large provenance/score JSON remains available on demand and may be lengthy. Item, ability and nature names retain existing source-language labels where canonical Chinese labels are unavailable. At narrow widths the source image precedes the opponent list. These usability choices await the user's judgment, as do the clarity of the uncertainty and fallback messages. Screenshot review by the agent and automated assertions are not independent human approval.

No new mechanics, item rules, Bayesian model, strategy suggestions, live capture, dataset rebuild, commit or push was performed.

## Reproduce without recomputing inference

Keep the local server running using the command in the review checklist. Then use fresh output directories:

```sh
node scripts/review_inference_ui.cjs .cache/m345/review-repeat
node scripts/verify_speed_replay.cjs 'http://127.0.0.1:8767/scripts/templates/speed_replay.html?battle=11&damage=1' .cache/m345/b11-repeat
node scripts/verify_speed_replay.cjs 'http://127.0.0.1:8767/scripts/templates/speed_replay.html?battle=12&damage=1' .cache/m345/b12-repeat
.venv/bin/python -m pytest -q tests/test_replay_presentation.py tests/test_empirical_measure.py tests/test_offensive_damage.py tests/test_hatterene_damage.py tests/test_m344_damage_review.py tests/test_item_policy.py
```

`review_inference_ui.cjs NEW_DIR --baseline` captures the current interface without controlled scenarios. The script refuses to overwrite a prior review directory and checkpoints screenshots plus their hashes as it proceeds. Chrome is used only for local rendering. No solver process is launched.
