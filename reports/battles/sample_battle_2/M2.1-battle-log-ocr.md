# M2.1 — Automated Battle Log OCR and structured event parsing

**The pipeline automatically recovers all 20 visible Turn 2 entries in chronological order. Strict OCR exact-text accuracy is 18/20 (90%); event types and the evaluated actor, target, side, and canonical-reference fields are correct.** The two exact-text failures are punctuation differences, retained in the output. These results are from one development sample and do not establish general battle-log reliability.

## Trainer and side identity

The preview shows **Hoshi** on the player-controlled purple team list and **训练家** on the red opponent list. Medium OCR reads both correctly (confidence 0.999 and 1.0, respectively). These are display names. No unique trainer identifier is visible in the reviewed preview; both `unique_trainer_id` values remain `null`. Stable internal side IDs are `self` and `opponent`, with `unknown` for unresolved participant ownership and `field` for weather/terrain.

Preview geometry and colored name-panel checks calibrate purple → self and red → opponent for this layout. A missing/unrecognized preview or low-confidence name does not silently establish color attribution. Trainer name evidence is kept separately from raw log observations. Distinct non-generic display names can support attribution; identical names are ambiguous. The generic string 训练家 alone does not establish ownership, even though it also appears as this opponent's display name.

For the initial generic Raichu withdrawal/Indeedee send-out, the contiguous matching trainer messages are corroborated by the immediately following Indeedee Psychic Surge row, whose red label has calibrated opponent ownership. Those backward associations carry their supporting entry IDs. Sneasler's send-out is corroborated by its adjacent red Psychic Seed row and prior opponent faint. “回来”/“上吧” and explicit “对手” provide independent text signals. Uncolored Archaludon effect/stat messages use the preceding executed-move actor; Politoed's effectiveness message uses the prior observed send-out context. Conflicting colors/text, ambiguous names, or a species observed on both sides preserve `unknown`.

Species identity does not serve as a globally unique ownership identifier. Regressions cover the same species active on both sides. Actor canonical references identify species/variants supported by the pinned dictionary; they are not per-Pokémon battle instance IDs. Raichu and Indeedee remain `species_only` with `canonical_identity: null` and `actor_variant_unresolved` uncertainty. Their form, regional variant, and Indeedee sex are not invented from text. This sample's remaining species have unique identities in the existing pinned index.

## Recognition and chronological assembly

The runtime uses the existing **PP-OCRv6 Medium recognizer**, through `ONNXOCRBackend`, CPU provider, batch size 1. The saved raw output records the pinned model revision/file hashes. This is the Medium model, not Tiny or a substituted text engine; no downloads or model modifications are performed.

The layout-specific detector checks the wide purple panel, multiple approximately equally spaced blue horizontal separators, and a bright scrollbar thumb. Message-column white-character projection detects individual text lines inside each row. The turn heading is OCR'd separately; a recognized 回合 number with confidence ≥0.75 validates the geometric detection. Row observations preserve untouched OCR text, per-line tokens and confidence, weighted row confidence, bounding boxes, image SHA-256, source frame/time, and row color. The log capture times retain the existing manifest's ±1-second grid uncertainty and are not event execution times.

Within each observed turn, views are sorted by scrollbar position, then deterministic timestamp/source tie-breakers. Ordered overlaps require at least two matching rows; fuzzy string comparison tolerates duplicate-view OCR differences without correcting any characters. Repeated identical messages at distinct sequence positions survive. Missing or ambiguous overlaps are reported instead of guessed. The representative is selected by complete-row preference, then OCR confidence, text length, and stable observation ID; reference text never selects a representative.

All nine log-visible samples (372–380 seconds) are detected. The six unobscured views provide 36 readable row occurrences and reconstruct all 20 entries. The three countdown views at 378–380 seconds are OCR'd and retained, but `COMMAND TIME` contamination causes their exclusion from assembly. This prevents truncated messages and overlay colors from replacing clear earlier observations. The policy depends on recognizing this overlay marker; other occlusions and layouts are not validated.

IDs derive from battle/source, observed turn, and assembled sequence position. Raw observation IDs derive from the frame hash and row bounds. Identical inputs, pinned model, and runtime produce stable IDs and output. IDs are source-local evidence identities, not cross-source deduplication promises; future fusion must associate independently observed candidates. Log order is relative to the available connected sequence; missing top-of-log coverage cannot prove that earlier entries do not exist.

## Source-independent event candidates

`BattleEvent` stores event type, side, actor/target canonical references, original Chinese text, optional log order, evidence source/observation IDs, OCR confidence, parsing confidence/uncertainty, typed attributes, and optional associated video evidence. `log_order` and `ocr_confidence` can be `null` for video-generated events; an `Evidence(source_type="video_observation", ...)` uses the same schema. The future tracker can consume this schema without reading OCR rows or opening the Battle Log.

The parser supports switch-out/send-out, executed moves, HP changes, ability/item activation, weather/terrain, stat changes, fainting, status changes, critical-hit and multi-hit messages. Effectiveness and move-effect messages preserve the additional reference rows rather than discarding them. Only a message announcing “使出了” creates a move-execution candidate; selection controls or named moves alone do not. Status/critical/multi-hit branches have text regressions but no occurrences in this OCR reference corpus. Weather/terrain recognition currently covers this sample's rain and Psychic Terrain phrases, not every possible field condition.

Raw rows, assembled entries, and parsed candidates are separate layers. Every event has `status: candidate`; none is automatically promoted to confirmed battle state. OCR confidence measures recognized characters, not message completeness or event truth. Low-confidence candidates do not seed later side context. Exact dictionary normalization preserves raw text and leaves corrupted names unresolved; no manually corrected strings enter predictions.

Moves 9 and 13 do not explicitly name targets in their rows. Their targets are associated with the following opposing HP-change messages, with supporting event IDs, `target_basis`, and `target_associated_from_sequence` uncertainty. The actor is the move user; for HP/stat/faint entries it is the affected Pokémon; effectiveness rows use the affected Pokémon as target. These role definitions are recorded in the reference dataset. Psychic Terrain is named through the immediately preceding Psychic Surge message. Stat-stage magnitude remains `null`.

HP changes use log endpoints, preserving absolute versus displayed-percent units. The old manual video's intermediate Armarouge 14% animation is not ingested as an extra damage event. No opponent absolute damage is inferred. Optional video links are attached **after prediction and scoring** through the previous manual reference alignment, explicitly marked `not_used_for_recognition`; M2.1 does not automate video alignment.

## Evaluation

Prediction/reference matching uses manually annotated viewport row positions (vertical intersection-over-union ≥0.8), not OCR text or predicted order. The recognizer/parser finish before the reference is loaded. The original reference hash and schema annotations are preserved in the fixture. Entries selected from their raw observations inherit the independently annotated event correspondence.

| --- | --- | --- |
| Battle Log UI detection | 9 TP, 31 TN, 0 FP, 0 FN | All 40 cached screenshots. |
| Log entry detection recall | 20/20 (100%) | Distinct reference entries recovered; zero unmatched/extra assembled entries. |
| Readable row-boundary recall | 36/36 (100%) | Six unobscured views; countdown rows excluded from this readable denominator. |
| Strict OCR exact-text accuracy | 18/20 (90%) | Selected entries; whitespace/line breaks ignored, punctuation and characters retained. |
| NFKC formatting-normalized OCR | 19/20 (95%) | Separately reported; not substituted for strict accuracy. |
| Readable occurrence exact OCR | 32/36 (88.9%) | Every readable duplicate occurrence, not just selected representatives. |

| Event-type parsing | 20/20 (100%) | Matched entries. |
| Actor attribution | 17/17 (100%) | Non-null actor reference fields. |

The parser's successful handling of these selected punctuation differences is semantic parsing success, not corrected OCR success. Rejected overlay views can also produce misleading row colors; their text and color evidence are not used by the final candidates. Confidence near 1.0 on a fragment illustrates why scroll coverage and overlay checks matter.

## Reproduction and validation

From the repository root, rerun the Medium OCR extraction, assembly, parser, and evaluation:

```sh
.cache/m15-accel-venv/bin/python scripts/evaluate_m21.py
```

This requires the existing cached survey images and pinned Medium model in `.cache/m15-onnx-medium`. It does not decode video. `--battle-id`, `--frames`, `--model-directory`, `--trainer-image`, `--ocr-output`, `--output`, `--reference`, and `--evaluation-output` select explicit input/output paths. The saved trainer screenshot avoids needing to repeat the opening-interval extraction. Missing trainer evidence leaves attribution uncalibrated rather than inventing names.

Reassemble, reparse, and evaluate the saved automatic OCR with the ordinary project environment, without loading a model or reading video:

```sh
.venv/bin/python scripts/evaluate_m21.py --reuse-ocr
.venv/bin/python -m pytest -q tests/test_battle_log.py
```

The implementation was exercised with the pinned Medium model and repeated parsing/evaluation was checked for byte-identical output. Focused regressions cover supported outcome messages, unresolved names, mirrored species, display-name ambiguity, evidence conflicts, low-confidence context protection, target association, HP units, unknown stat stages, stable IDs, repeated messages, overlay exclusion, UI geometry at three scales, and negative screenshots. Saved automatic OCR is also checked against the independent reference evaluation. This is a development sample; synthetic parser regressions do not establish OCR recall for unobserved event types.

Validation: **37 focused regressions passed**; the full suite passed **227 tests in 62.47 seconds**, with the existing Paddle ccache warning. `git diff --check` passed. Replaying the saved automatic OCR produced byte-identical event and evaluation JSON. Source/reference/trainer hashes and every report link were verified. Missing critical-hit/multi-hit sides are explicitly uncertain. No commit or push was performed.
