# M2.2.2 — Stateful mechanics

Continued the interrupted working tree and extended the existing M2.2 state tracker and M2.2.1 offline viewer. No commit or push was made.

## Infrastructure and lifecycle

`tracking/mechanics.py` supplies a registry of independent mechanic handlers. Records support per-action, per-turn, per-entry, per-instance, per-side, and global ownership, typed knowledge facts, provenance, trigger event IDs, explicit activation conditions, persistence conditions, reset conditions, and evidence-supported expiration. Scope describes ownership/lifetime intent; it does not invent automatic game resets. Generic observations and resets specify their facts and timing explicitly.

Stable `pokemon_instance_id` values continue to identify party members across switches and transformations. A separate `field_entry.entry_id` identifies each observed send-out. Initial active Pokémon receive a partial-entry identifier, with zero observed send-outs; this does not establish fresh-entry mechanic eligibility. Ambiguous identity binding continues to defer rather than merge instances by species.

Handlers run inside the existing transactional replay path. Rejected events leave gameplay state unchanged and record a conflict. Corrections, retractions, deduplication, serialization, and replay rebuild mechanic state together with the existing battle state. Engine envelopes now serialize the rule profile and handler identifiers; custom handlers require a matching registry on restoration. Legacy state fields remain readable and preserved.

| Mechanic | Activation | Persistence | Reset / uncertainty |
| --- | --- | --- | --- |
| Protect chain | Executed family attempt and explicitly linked success/failure outcome | Established consecutive-success count, independently from pending attempt | Explicit reset; opt-in supported failure, completed non-family action, switch/faint, or covered turn expiry. Missing outcomes/history invalidate continuity. UI selection and phase observations do not reset it. |
| Protean | Observed activation, optionally followed by observed resulting types | Activation latch within the same entry and ability instance | Opt-in once-per-entry rules reset on observed re-entry or explicit new ability instance. A transformation alone does not establish a reset. |
| Unburden | Supported held-item loss with established, unsuppressed ability, or explicit mechanic evidence | Trigger latch distinct from currently applicable effect; item presence and suppression condition the effect | Opt-in switch/faint and ability-instance termination clear the latch. Reacquisition or suppression suspends the effect. Transfers refresh both affected owners. Speed multiplier is separate from Speed stages. |
| Entry abilities | Observed activation while active | Activation evidence and count for current entry | New entry separates activation history. Weather, terrain, and stat consequences still require their own events. |

The built-in entry-ability set currently covers Intimidate, Drought, Drizzle, and Psychic Surge. The registry permits additional handlers without changing the core Pokémon schema. Protean, Unburden, and Protect state can coexist without sharing counters.

## Evidence policy and provisional rules

The default profile is `champions-evidence-only-v1`, labeled `champions_rules_unverified`. It preserves observed attempts, outcomes, activations, types, item changes, and explicitly supported resets. It does **not** publish numerical Protect success probabilities, infer Protean once-per-entry eligibility, or derive an Unburden Speed multiplier from item loss.

`showdown-champions-reference-v1` is explicitly opt-in and labeled `simulator_reference_only`. The inherited reference metadata points to Pokémon Showdown commit `3a766f2cfb5e51c1e428cfe87d0dba91a8f01640`. It is software-reference provenance, not official Champions verification. This continuation did not perform a new source audit.

All exact game-rule details in that profile remain **provisional**: Protect's divisor of three, denominator cap of 729, supported protection family and reset behavior; Protean's once-per-entry and ability-instance semantics; and Unburden's twofold multiplier, trigger retention, suppression, and reset behavior. Tests validate the selected profile's implementation, not the correctness of those rules in Pokémon Champions. No Pokémon move/ability availability is inferred from the reference profile.

Protect queries return a rational probability only when an established count and opted-in probability rules support it. Unknown history returns a bounded range, pending outcomes block an exact result, and probabilities remain conditional on other move failure checks. Current types stay unknown unless observed; native-type reversion is not guessed.
