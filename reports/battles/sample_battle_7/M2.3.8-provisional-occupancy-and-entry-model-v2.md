## Occupancy and prospective identity

The authoritative objects remain the existing `PokemonState`, `SideState.active_slots`, and `active_entry_episodes`. There is no second identity database or duplicate slot ledger. Occupancy labels are derived from those objects:

| Label | Meaning |
|---|---|
| `vacant` | Supported vacancy, with no unresolved arrival that prevents assigning vacancy |
| `occupied_unidentified` | A current episode occupies the slot; its species Fact remains unknown |
| `occupied_identified` | A current episode occupies the slot and has independently supported species |
| `placement_unresolved` | An arrival cannot yet be placed, or no initial occupancy has been established |

Complete live send-outs require supported side grammar, OCR confidence at least 0.95, a complete punctuated announcement, finite timestamp and timestamp-matching video-message provenance. Unknown species alone no longer blocks occupancy admission. Other policy uncertainties remain subject to the existing policy. An incomplete high-confidence announcement still abstains.

A single explicitly supported vacancy determines placement. The existing qualified two-member opening adapter supplies its established literal-order placement evidence. A supplied slot without those supports is not treated as proof. Ambiguous arrivals remain pending through the existing `unplaced_entries` representation rather than selecting a slot by roster order or 3D screen position.

Each provisional episode retains the literal display reference, trainer evidence, original arrival event ID/timestamp and source evidence. Species, form, HP, status, item, ability, moves, types and hidden configuration stay unknown until their own evidence arrives. Persistent party identity remains unproven. Repeated source occurrences do not create duplicate occupants; a later genuine entry does not merge biological identity merely because a nickname or species repeats.

The same provisional instance is upgraded by independently accepted HUD evidence. Its arrival timestamp stays fixed; `species_resolution_time` and resolution provenance are recorded separately. Earlier snapshots retain `species=None`, and the original arrival receipt's copied episode remains unidentified. A withdrawal or faint can close the named provisional episode before species resolution; an observed forced departure is handled by the same lifecycle. A move such as Roar alone does not establish a successful forced departure.

The decision-facing and evidence projections expose all four occupancy labels. Hidden-state seeding tolerates unknown species without constructing species constraints. W reports previous occupancy separately and can resolve an unidentified current instance from admissible command HUD identity without replacing that instance or counting it as an occupancy correction. Existing strict-single-frame nickname gates still abstain without accepted prefix support.

## Entry-model investigation and bounded prototype

The existing recognizers match transparent **UI sprite images**, or silhouettes isolated against chromatic UI panels. `recognition/sprite_shape.py` explicitly excludes rendered scene models. The pinned visual manifest contains **393 assets** from source commit `4953be0b8f2eee5415255c4e0bb2bdec6065c75b`; inspected assets for the opponent preview are 120×120 RGBA UI images, not multiview in-battle 3D templates. Their local hashes match the pinned index. Existing OCR models do not supply scene-species classification. No local scene-domain validation or score calibration was found in these established recognizers/assets.

Correlating those UI sprites against the 3D scene would not yield a validated species prediction. No such inference was run, no new model was loaded, and no unsupported automatic Pelipper result is reported. The user/agent Pelipper identification is retained only as a reference annotation in the local asset-investigation evidence, outside the probe's classification inputs.

`recognition/entry_model.py` implements a concrete **entry-triggered, saved-frame probe**. It requires an applied send-out episode, restricts candidate species to all six independently resolved opponent preview rows observed before the entry, and examines at most four saved frames between two and four seconds afterward, with a hard maximum five-second configuration window. It checks source PNG hashes and source-PTS timestamps. It does not consume nickname identity, predicted species, model-position slot guesses, later HUD labels or human reference answers. Tests verify that replacing future HUD labels cannot change the probe output.

For both entries the candidate IDs are **260, 279, 302, 398, 1013, 1018**, derived from the independently acquired six-Pokémon preview, not a probability prior. The probe records method `entry-scene-probe-abstain-v1`, image provenance, all candidate IDs, `score=None`, `species_id=None`, `confidence=None`, and an explicit unsupported-classifier/calibration reason. Scores are missing, not zero probabilities. Acceptance is disabled; the validated scene-classifier registry is empty. Human reference or unregistered automatic-looking metadata cannot resolve an unidentified episode.

The prototype is invoked by the saved-evidence validation tool after supported entries. A live entry-model acquisition/classification path is not enabled in the production video adapter, and sampling/OCR frequency is unchanged. The production StateEngine occupancy fix is active through the existing identity/continuity profiles.

### Bounded evaluation plan for actual model recognition

1. Prepare a small independently labeled scene-reference gallery, with multiple poses/views per candidate species, from separate evidence. The current UI sprites and the human-labeled Papudo test frames cannot serve as a validated scene gallery. Keep form IDs and source/image hashes through the existing canonical identity system.
2. After a supported entry, retain the four-frame/five-second cap. Stop or abstain if another entry/departure, multiple entering models, severe clipping or ambiguous foreground association prevents identifying the newly entering object. Do not derive a doubles slot from 3D screen coordinates.
3. Prototype lightweight foreground masks, normalized color/edge descriptors and gallery comparison using the existing local image-processing stack. For a reliable six-species preview, bound comparisons to six candidates and a small fixed number of reference views. Do not enable a continuously running general-purpose vision model.
4. Collect independently labeled positive, confusing-species, form, occlusion and out-of-gallery cases from other entries. Freeze score and top-two-margin thresholds using calibration evidence; require two independent agreeing frames, sufficient object visibility and a held-out high-precision selective-acceptance result. A target such as 99% selective precision is an evaluation goal, not a measured result or a currently valid numerical confidence. Until score distributions justify conservative thresholds, acceptance remains disabled.
5. Evaluate the Papudo 502s frames only after freezing the method and thresholds. Compare predictions with the held-out human reference and separately with the later 520/521s HUD. Report abstentions, all candidate scores, wrong confident predictions, runtime and memory. Later HUD identity must never be a classifier input or the early frame's answer.
6. Only a versioned classifier with a pinned validation artifact may emit an independent `cached_entry_model` assertion tied to the original send-out. The existing prospective-resolution adapter can then upgrade that current episode at the model-evidence time. Model disagreement remains an explicit uncertainty gate and cannot silently replace a message/HUD identity.

This plan requires additional independently labeled scene assets and validation; this task does not crawl, download, train or claim a successful classifier.
